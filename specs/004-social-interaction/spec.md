## User Scenarios & Testing *(mandatory)*

### User Story 1 - 마을 소식에서 다른 사람의 글 발견하기 (Priority: P1)

누구나(방문자 포함) 광장 게시판의 마을 소식 입구로 들어가 마을 전체 블로그의 공개 글을 최신순으로 훑어보고, 마음에 드는 글이나 블로그로 이동한다. 다른 블로그를 자연스럽게 발견하게 한다는 제품 목표(1.2 목표 3)의 핵심 통로다.

**Why this priority**: 교류의 출발점이다. 글을 발견하지 못하면 댓글·공감·이웃도 일어나지 않는다. 로그인 없이도 가치를 준다.

**Independent Test**: 여러 블로그에 공개·비공개 글을 섞어 만든 뒤, 로그인하지 않은 상태로 마을 소식을 열어 공개 글만 최신순 8개씩 보이는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 로그인하지 않은 방문자, **When** 마을 소식을 열면, **Then** 화면이 정상으로 열리고 [🏘 마을 전체] 탭만 보이며 [💛 이웃 새 글] 탭은 없다.
2. **Given** 여러 블로그에 공개 글 9개 이상과 비공개 글이 있음, **When** 마을 소식 1페이지를 열면, **Then** 블로그 구분 없이 작성 시각 최신순으로 공개 글 8개만 보이고, 9번째 글은 2페이지에 나온다.
3. **Given** 글 주인 또는 관리자로 로그인, **When** 마을 소식을 열면, **Then** 자신의 비공개 글을 포함해 어떤 비공개 글도 보이지 않는다.
4. **Given** 마을 소식의 글 카드, **When** 작성자 줄(캐릭터·닉네임·블로그 이름)을 누르면, **Then** 그 블로그 홈으로 가고, 카드의 나머지를 누르면 그 글 상세로 간다.
5. **Given** 공개 글이 하나도 없는 마을, **When** 마을 소식을 열면, **Then** `아직 마을에 글이 없어요. 첫 글의 주인공이 되어 보세요! ✏️`와 인기 태그 칸의 `아직 태그가 없어요`가 보인다.
6. **Given** 누군가 새 공개 글을 발행함, **When** 마을 소식을 다시 열면, **Then** 그 글이 1페이지 맨 위에 나온다.
7. **Given** 페이지 번호에 `abc`, `0`, `2.5`, `1e300`, 아주 큰 수를 넣음, **When** 마을 소식을 열면, **Then** 오류 화면 없이 1페이지가 보인다.

### User Story 2 - 글에 댓글 쓰고 내 댓글 지우기 (Priority: P1)

온보딩을 마친 회원은 볼 수 있는 글(공개 글 또는 내 글) 아래에 댓글을 남기고, 자기가 쓴 댓글을 지운다. 남의 글에 댓글을 쓰면 하루 정해진 횟수까지 활동 보상을 받는다. 방문자는 댓글을 읽기만 한다.

**Why this priority**: 블로그 간 교류의 가장 기본적인 수단이며 우선순위 M이다.

**Independent Test**: 회원 A의 공개 글에 회원 B가 댓글을 등록·삭제해 보고, 목록·댓글 수·보상 변화를 확인한다.

**Acceptance Scenarios**:

1. **Given** 온보딩을 마친 회원이 남의 공개 글 상세를 봄, **When** 댓글을 쓰고 [댓글 등록]을 누르면, **Then** 새로고침 없이 목록 맨 아래에 내 댓글이 나오고 입력칸이 비워지며 경험치 5·코인 5 보상을 받는다.
2. **Given** 회원이 내 글 상세를 봄, **When** 댓글을 등록하면, **Then** 댓글은 등록되지만 보상은 없다.
3. **Given** 오늘(한국 시간 0시 기준) 댓글 보상을 받은 적 없는 회원, **When** 같은 날 남의 글에 댓글 11개를 쓰면, **Then** 11개 모두 등록되고 보상은 10번만 들어온다.
4. **Given** 공백만 입력함, **When** 등록하면, **Then** `댓글을 적어 주세요`가 나오고 저장되지 않는다.
5. **Given** 남의 비공개 글 또는 없는 글을 대상으로 요청을 조작함, **When** 댓글을 보내면, **Then** `글을 찾을 수 없어요`가 나오고 저장되지 않는다.
6. **Given** 내가 쓴 댓글, **When** [삭제] → 확인 창 `댓글을 삭제할까요?`에서 확인하면, **Then** 그 자리에 `삭제된 댓글이에요`가 흐리게 남고 `💬 댓글 N`이 1 줄며, 지운 댓글의 내용은 화면으로 전달되지 않는다. 이미 받은 보상은 그대로다.
7. **Given** 답글이 달린 내 댓글, **When** 삭제하면, **Then** 답글은 그대로 남는다.
8. **Given** 남의 댓글 또는 이미 삭제된 댓글, **When** 요청을 조작해 삭제를 보내면, **Then** 아무것도 바뀌지 않고 문구도 없다.
9. **Given** 방문자 또는 온보딩 전 회원, **When** 글 상세를 보면, **Then** 입력칸 대신 `로그인하면 댓글을 남길 수 있어요`가 보이고 [답글] [삭제] 버튼이 없다.

### User Story 3 - 마음에 드는 글에 공감(♥)하기 (Priority: P2)

온보딩을 마친 회원은 글에 공감을 한 번 남기고, 다시 눌러 취소할 수 있다. 남의 글에 공감하면 글 주인이 보상을 받는다. 방문자는 공감 수만 본다.

**Why this priority**: 우선순위 M이지만 댓글보다 가벼운 반응이고, 댓글 없이도 독립적으로 동작한다.

**Independent Test**: 회원 B가 회원 A의 공개 글에서 공감을 눌렀다 취소했다 반복하며 수, 하트 상태, A의 코인을 확인한다.

**Acceptance Scenarios**:

1. **Given** 온보딩을 마친 회원이 공감하지 않은 글, **When** [♡ 공감 N]을 누르면, **Then** 즉시 [♥ 공감 N+1]로 바뀌고 처리가 끝나면 저장된 값으로 다시 보인다.
2. **Given** 이미 공감한 글, **When** 다시 누르면, **Then** 취소되어 [♡ 공감 N]으로 돌아가고 수가 1 준다.
3. **Given** 남의 글, **When** 처음 공감하면, **Then** 글 주인이 경험치 2·코인 2를 받는다 (글 주인 기준 하루 20번까지).
4. **Given** 같은 사람이 같은 글에 공감 → 취소 → 공감을 반복, **When** 반복이 끝나면, **Then** 글 주인의 보상은 처음 한 번뿐이다.
5. **Given** 내 글, **When** 공감하면, **Then** 저장되고 수에 들어가지만 보상은 없다.
6. **Given** 방문자 또는 온보딩 전 회원, **When** 글 상세를 보면, **Then** 공감 수는 보이지만 버튼은 비활성이고 안내 `로그인하면 공감할 수 있어요`가 붙는다.
7. **Given** 남의 비공개 글이나 범위 밖·숫자가 아닌 글 식별자로 요청을 조작, **When** 공감을 보내면, **Then** 오류 화면 없이 아무것도 저장되지 않고 하트와 수는 누르기 전으로 돌아간다.
8. **Given** 같은 글, **When** 글 카드와 글 상세를 비교하면, **Then** 카드의 `♥ N`과 상세의 `공감 N`이 같다.

### User Story 4 - 이웃 추가하고 이웃 새 글 모아 보기 (Priority: P3)

온보딩을 마친 회원은 다른 회원의 블로그 홈에서 그 블로그를 이웃으로 추가·취소하고, 마을 소식의 [💛 이웃 새 글] 탭에서 이웃 블로그의 공개 글만 모아 본다.

**Why this priority**: 우선순위 S. 마을 소식과 블로그 홈이 있어야 의미가 있고, 없어도 기본 교류는 가능하다.

**Independent Test**: 회원 B가 회원 A의 블로그를 이웃 추가한 뒤 이웃 새 글 탭에 A의 공개 글만 나오는지, 취소하면 빠지는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 다른 회원의 블로그 홈, **When** [+ 이웃 추가]를 누르면, **Then** 처리가 끝난 뒤 버튼이 [✓ 이웃]으로, `이웃 N`이 N+1로 바뀐다. 다시 누르면 확인 창 없이 둘 다 원래대로 돌아온다.
2. **Given** 이웃 추가한 블로그, **When** 이웃 새 글을 열면, **Then** 이웃 추가하기 전에 쓴 글을 포함해 그 블로그의 공개 글이 최신순 8개씩 나오고, 비공개 글과 이웃이 아닌 블로그의 글은 나오지 않는다.
3. **Given** 이웃을 취소함, **When** 이웃 새 글을 다시 열면, **Then** 그 블로그의 글이 빠진다.
4. **Given** 내 블로그 홈, **When** 화면을 보면, **Then** 이웃 버튼이 없고, 요청을 조작해 나 자신을 이웃 추가해도 저장되지 않는다.
5. **Given** 방문자, **When** 블로그 홈과 마을 소식을 보면, **Then** `이웃 N`은 보이지만 이웃 버튼과 [💛 이웃 새 글] 탭이 없고, 이웃 새 글 주소로 직접 들어가면 첫 화면으로 이동한다. 온보딩 전 회원은 온보딩 화면으로 이동한다.
6. **Given** 이웃이 없거나 이웃의 공개 글이 없음, **When** 이웃 새 글을 열면, **Then** `아직 이웃이 없거나 이웃의 새 글이 없어요.` / `마을 소식에서 마음에 드는 블로그를 이웃으로 추가해 보세요.` 두 줄이 보이고 "마을 소식"은 마을 소식으로 가는 링크다.
7. **Given** 없는 회원이나 블로그가 없는(온보딩 전) 회원을 대상으로 요청을 조작, **When** 이웃 추가를 보내면, **Then** 이웃 관계가 생기지 않고 오류도 나지 않는다.
8. **Given** 이웃 추가·취소, **When** 처리가 끝나면, **Then** 경험치·코인은 바뀌지 않는다.

### User Story 5 - 댓글에 답글 달기 (1단계) (Priority: P4)

온보딩을 마친 회원은 삭제되지 않은 원댓글에 답글을 달아 대화를 이어 간다. 답글에는 다시 답글을 달 수 없다(1단계).

**Why this priority**: 우선순위 C. 댓글 기능 위에 얹는 편의 기능이다.

**Independent Test**: 원댓글 하나에 답글 두 개를 달고, 순서·들여쓰기·버튼 유무·원댓글 삭제 후 표시를 확인한다.

**Acceptance Scenarios**:

1. **Given** 삭제되지 않은 원댓글, **When** [답글]을 누르면, **Then** 원댓글 아래에 `답글을 남겨 주세요` 입력칸이 열리고 버튼이 [답글 취소]로 바뀐다.
2. **Given** 열린 답글 입력칸, **When** [답글 등록]을 누르면, **Then** 새로고침 없이 그 원댓글의 답글 맨 아래에 들여쓰기로 나오고, 입력칸은 비워지고 닫힌다.
3. **Given** 답글, **When** 화면을 보면, **Then** 답글에는 [답글] 버튼이 없다.
4. **Given** 답글을 대상으로 요청을 조작해 답글의 답글을 보냄, **When** 저장되면, **Then** 원댓글의 답글로 붙는다.
5. **Given** 다른 글의 댓글이나 없는 댓글을 부모로 지정해 조작, **When** 보내면, **Then** 답글로 붙지 않고 일반 댓글로 저장된다.
6. **Given** 같은 날 남의 글에 댓글 6개와 답글 5개를 씀, **When** 보상을 확인하면, **Then** 댓글 보상은 합쳐서 10번(경험치 50·코인 50)만 들어오고, 내 글에 단 답글은 보상이 없다.
7. **Given** 답글 2개가 달린 원댓글, **When** 원댓글을 삭제하면, **Then** 원댓글 자리에 `삭제된 댓글이에요`가 남고 답글 2개는 그대로 보이며 `💬 댓글 2`가 된다.
8. **Given** 방문자, 온보딩 전 회원, 또는 삭제된 원댓글, **When** 화면을 보면, **Then** [답글] 버튼이 없다.

### Edge Cases

- 공백만 쓴 댓글·답글 → `댓글을 적어 주세요`. 1000자를 넘으면 `댓글은 1000자까지예요`. (SOC-01, SOC-02)
- 글·부모 댓글 식별자를 허용 범위(1~2,147,483,647 정수)를 넘는 값(예: `99999999999`)으로 조작 → `잘못된 요청이에요`, 저장 안 됨. 삭제·공감 요청의 범위 밖 식별자는 오류 화면 없이 아무것도 바뀌지 않는다. (SOC-01, SOC-02, SOC-03)
- 등록·삭제·공감 요청 시점에 로그인이 풀려 있음 → 첫 화면으로 이동. (SOC-01, SOC-03)
- 삭제 확인 창에서 [취소] → 아무 일도 없다. (SOC-01)
- 답글 입력칸을 연 사이 원댓글이 삭제됨 → 막지 않고 `삭제된 댓글이에요` 아래 답글로 저장된다. (SOC-02)
- 다른 탭에서 이미 공감한 글의 예전 화면에서 [♡]를 누름 → 서버는 취소로 처리하고 잠깐 ♥였다가 ♡로 돌아온다. (SOC-03)
- 공감 처리 중 다시 누름 → 버튼이 비활성이라 눌리지 않는다. (SOC-03)
- 글 주인이 하루 공감 보상 20번을 다 받음 → 공감은 저장되고 보상은 없다. 이 공감은 보상 기록이 없어 다음 날 취소 후 다시 공감하면 그날 상한 안에서 보상된다. (SOC-03)
- 같은 블로그에 대한 이웃 요청이 겹침 → 이웃 관계는 하나만 남는다. (SOC-04)
- 마지막보다 큰 페이지 번호 → 빈 목록이 되어 글이 있어도 빈 화면 문구가 나온다. (SOC-04, SOC-05)
- 회원 자체가 지워지면 그 회원의 이웃 관계(양방향)·공감·댓글이 함께 사라진다. 글이 지워지면 그 글의 댓글·공감도 사라지며, 이미 지급된 보상은 회수하지 않는다. (SOC-01, SOC-03, SOC-04)

## Requirements *(mandatory)*

### Functional Requirements

| ID | 요구사항 | 우선 | 상태 |
|---|---|---|---|
| SOC-01 | 회원은 글에 댓글을 쓰고, 자기 댓글을 삭제할 수 있다 | M | ✅ |
| SOC-02 | 댓글에 답글(1단계)을 달 수 있다 | C | ✅ |
| SOC-03 | 회원은 글에 공감(♥)할 수 있다. 한 글에 한 번만 가능하고 취소할 수 있다 | M | ✅ |
| SOC-04 | 다른 블로그를 이웃으로 추가하고, 이웃의 새 글을 모아볼 수 있다 | S | ✅ |
| SOC-05 | 마을 전체의 최신 공개 글을 볼 수 있다 | M | ✅ |

**댓글 (SOC-01)**

- **FR-001**: 시스템은 온보딩을 마친 회원이 공개 글 또는 자기 글에 댓글을 등록할 수 있게 해야 한다. 방문자와 온보딩 전 회원에게는 입력칸 대신 `로그인하면 댓글을 남길 수 있어요`를 보여 주고, 온보딩 전 회원이 `로그인`을 누르면 온보딩으로 안내해야 한다. (SOC-01)
- **FR-002**: 시스템은 댓글 내용을 앞뒤 공백 제거 후 1~1000자로 제한해야 한다. 공백뿐이면 `댓글을 적어 주세요`, 1000자를 넘으면 `댓글은 1000자까지예요`를 보여 주고 저장하지 않아야 한다. (SOC-01)
- **FR-003**: 시스템은 없는 글이나 남의 비공개 글에 대한 댓글 요청을 `글을 찾을 수 없어요`로 거부해야 하고, 허용 범위를 넘는 글 식별자는 `잘못된 요청이에요`로 거부해야 한다. (SOC-01)
- **FR-004**: 시스템은 댓글을 일반 텍스트로만 보여 줘야 한다. 줄바꿈은 유지하고, HTML은 글자 그대로 보이며, 서식·자동 링크는 없다. (SOC-01)
- **FR-005**: 시스템은 남의 글에 댓글을 등록한 회원에게 경험치 5·코인 5를 한국 시간 하루 10번까지 지급해야 하며(답글 포함 합산), 내 글에 쓴 댓글에는 지급하지 않아야 한다. 상한을 넘으면 댓글은 등록하되 보상과 안내는 없다. 댓글 저장과 보상 지급은 함께 성공하거나 함께 실패해야 한다. (SOC-01)
- **FR-006**: 시스템은 댓글을 오래된 순(작성 시각, 같으면 등록 순)으로 페이지 나누기 없이 모두 보여 줘야 하며, 각 댓글에 작성자의 현재 캐릭터·닉네임(누르면 그 사람 블로그)·작성 시각(한국 시간 24시간제 `YYYY. MM. DD. HH:MM`)·내용을 표시해야 한다. (SOC-01)
- **FR-007**: 시스템은 작성자 본인만 자기 댓글을 삭제할 수 있게 해야 한다. 삭제 전 `댓글을 삭제할까요?` 확인을 받고, 권한은 화면이 아니라 서버에서 확인하며, 남의 댓글·이미 삭제된 댓글·범위 밖 식별자에 대한 삭제 요청은 아무것도 바꾸지 않고 문구 없이 끝나야 한다. (SOC-01)
- **FR-008**: 시스템은 삭제된 댓글 자리를 남겨 작성자·시각은 그대로 두고 내용 자리에 `삭제된 댓글이에요`(흐린 기울임)를 보여 줘야 하며, 지운 내용은 화면으로 보내지 않고 [답글] [삭제] 버튼을 없애야 한다. 삭제해도 이미 받은 보상은 회수하지 않는다. [NEEDS CLARIFICATION: 삭제된 댓글 자리 처리 — 현재처럼 답글이 없어도 항상 자리와 작성자를 남길지, 답글 없는 댓글은 완전히 없애고 남길 때도 작성자·시각을 숨길지?] (SOC-01, SOC-02)
- **FR-009**: 시스템은 `💬 댓글 N`, 글 카드의 `💬 N`, 관리자 통계의 댓글 수에서 삭제된 댓글을 빼고 답글은 포함해 세야 한다. 댓글이 없으면 `💬 댓글 0`과 입력칸(또는 로그인 안내)만 보여 준다. (SOC-01)
- **FR-010**: 시스템은 댓글 삭제 권한을 정해진 사람에게만 줘야 한다. 현재는 작성자 본인만 지운다. [NEEDS CLARIFICATION: 삭제 권한을 작성자 외에 그 글의 블로그 주인과 관리자에게도 줄지? (지금 관리자는 글 통째 삭제만 가능)] (SOC-01)
- **FR-011**: 시스템은 댓글 작성 자격을 정해진 사용자에게만 줘야 한다. 현재는 온보딩을 마친 회원만 쓴다. [NEEDS CLARIFICATION: 방문자도 이름+비밀번호로 댓글을 쓰고 그 비밀번호로 지우게 할지? 허용하면 스팸 대책과 요약 문장("회원은 …")도 함께 정해야 한다] (SOC-01)
- **FR-012**: 시스템은 등록 처리 중 버튼을 `등록 중...`으로 바꾸고 누를 수 없게 해야 하며, 오류 문구는 버튼 옆에 작게 보여 주고, 등록에 성공하면 입력칸을 비워야 한다. (SOC-01)
- **FR-013**: (알려진 문제) 현재 서버가 오류(`댓글을 적어 주세요`, `글을 찾을 수 없어요`)를 돌려줘도 입력칸이 비워져 쓰던 내용이 사라진다. 오류일 때 입력 내용을 남겨야 한다. (SOC-01)

**답글 (SOC-02)**

- **FR-014**: 시스템은 온보딩을 마친 회원에게 삭제되지 않은 원댓글에만 [답글] 버튼을 보여 줘야 하며, 답글에는 [답글] 버튼이 없어야 한다(1단계). (SOC-02)
- **FR-015**: 시스템은 답글을 원댓글 바로 아래에 들여쓰기로, 원댓글별로 오래된 순으로 보여 줘야 하며, 새 답글은 그 원댓글의 답글 맨 아래에 붙여야 한다. 답글 한 줄의 표시는 댓글과 같고 [삭제]는 내 답글에만 있다. (SOC-02)
- **FR-016**: 시스템은 답글 입력칸(`답글을 남겨 주세요`)을 원댓글마다 따로 열 수 있게 하고, [답글 취소]로 닫으면 쓰던 내용을 버리며, 등록에 성공하면 입력칸을 비우고 닫아야 한다. (SOC-02)
- **FR-017**: 시스템은 답글 내용에 댓글과 같은 규칙과 오류 문구를 적용하고(FR-002~FR-004), 허용 범위를 넘는 부모 식별자는 `잘못된 요청이에요`로 거부해야 한다. (SOC-02)
- **FR-018**: 시스템은 조작된 부모 지정을 다음처럼 처리해야 한다: 답글을 부모로 지정하면 그 원댓글의 답글로, 없는 댓글이나 다른 글의 댓글을 지정하면 일반 댓글로 저장한다. 삭제된 원댓글에 대한 답글은 막지 않는다. (SOC-02)
- **FR-019**: 시스템은 남의 글에 단 답글을 댓글 보상 대상으로 보고 댓글과 합쳐 하루 10번까지 지급해야 한다(남의 글이면 내 댓글에 단 답글도 포함, 내 글에 단 답글은 제외). (SOC-02)
- **FR-020**: (알려진 문제) 답글 입력칸을 열어 둔 채 그 원댓글을 삭제하면 [답글 취소]가 사라져 입력칸이 열린 채 남는다. 등록하거나 페이지를 다시 열어야 닫힌다. (SOC-02)
- **FR-021**: (알려진 문제) 숫자가 아니거나 0 이하인 부모 식별자로 조작하면 우리말이 아닌 영어 기본 검증 문구가 보인다. (SOC-02)

**공감 (SOC-03)**

- **FR-022**: 시스템은 온보딩을 마친 회원이 공개 글 또는 내 글에 공감할 수 있게 하고, 한 사람이 한 글에 남길 수 있는 공감을 최대 1개로 보장해야 한다(동시 요청 포함). (SOC-03)
- **FR-023**: 시스템은 공감 버튼 하나로 공감과 취소를 전환해야 하며, 공감인지 취소인지는 서버가 현재 상태를 보고 정해야 한다(내 공감이 있으면 취소). (SOC-03)
- **FR-024**: 시스템은 누르는 즉시 하트와 수를 바꿔 보여 주고, 처리 중에는 버튼을 비활성으로 하며, 처리가 끝나면 저장된 값으로 다시 보여 줘야 한다. 저장되지 않았으면(글 삭제·비공개 전환·조작) 문구 없이 누르기 전 상태로 돌아간다. (SOC-03)
- **FR-025**: 시스템은 남의 글에 공감하면 글 주인에게 경험치 2·코인 2를 글 주인 기준 하루 20번까지 지급하되, 같은 사람·같은 글로 받는 보상은 최대 1번이어야 한다. 내 글 공감은 보상이 없고, 취소하거나 글을 지워도 받은 보상은 회수하지 않는다. 공감 저장과 보상은 함께 성공하거나 함께 실패해야 한다. (SOC-03)
- **FR-026**: 시스템은 글 상세에 `♡ 공감 N` / `♥ 공감 N`(N = 글 주인 본인을 포함한 전체 공감 수)과 눌림 상태를 보조 기술에도 알리고, 글 카드에 `♥ N`(0 포함)을 같은 수로 보여 줘야 한다. 누가 공감했는지는 보여 주지 않고 글 주인에게 알림도 없다. (SOC-03)
- **FR-027**: 시스템은 방문자와 온보딩 전 회원에게 공감 수를 보여 주되 버튼은 비활성으로 하고 `로그인하면 공감할 수 있어요` 안내를 붙여야 한다. (SOC-03)
- **FR-028**: (알려진 문제) 비활성 버튼은 마우스를 올려도 반응하지 않아 방문자 안내가 보이지 않을 수 있고, 터치 화면에서는 보기 어렵다. (SOC-03)
- **FR-029**: (알려진 문제) 같은 사람이 두 탭에서 동시에 처음 공감하면 공감은 1개만 저장되지만 늦은 쪽 탭에 오류 화면(`잠깐 문제가 생겼어요`)이 뜬다. (SOC-03)

**이웃 (SOC-04)**

- **FR-030**: 시스템은 온보딩을 마친 회원이 다른 회원의 블로그 홈에서 이웃 추가·취소를 할 수 있게 해야 한다. 이웃이 아니면 `+ 이웃 추가`, 이웃이면 `✓ 이웃`을 보여 주고, 취소에는 확인 창이 없으며, 버튼과 수는 서버 처리가 끝난 뒤에 바뀐다. 이웃 버튼은 블로그 홈에만 있다. (SOC-04)
- **FR-031**: 시스템은 자기 자신, 없는 회원, 블로그가 없는(온보딩 전) 회원을 이웃으로 추가하지 않아야 하며 이때 오류를 보여 주지 않는다. 같은 회원 쌍의 이웃 관계는 최대 1개여야 한다(겹친 요청 포함). (SOC-04)
- **FR-032**: 시스템은 블로그 홈 정보 줄에 `@{주소} · 글 {N} · 이웃 {N}`을 모두에게 보여 줘야 하며, `이웃 N`은 이 블로그 주인을 이웃 추가한 사람 수(단위 없음)다. (SOC-04)
- **FR-033**: 시스템은 마을 소식의 [💛 이웃 새 글] 탭에서 내가 이웃 추가한 블로그의 공개 글만(추가 전에 쓴 글 포함) 마을 소식과 같은 카드 규칙(8개씩, 최신순, 작성자 표시)으로 보여 줘야 한다. 제목은 `💛 이웃 새 글`, 인기 태그는 마을 전체 공개 글 기준이다. (SOC-04)
- **FR-034**: 시스템은 방문자와 온보딩 전 회원에게 이웃 버튼과 [💛 이웃 새 글] 탭을 보여 주지 않고, 이웃 새 글에 직접 들어오면 방문자는 첫 화면, 온보딩 전 회원은 온보딩으로 보내야 한다. (SOC-04)
- **FR-035**: 시스템은 이웃이 없거나 이웃의 공개 글이 없을 때 `아직 이웃이 없거나 이웃의 새 글이 없어요.` / `마을 소식에서 마음에 드는 블로그를 이웃으로 추가해 보세요.`("마을 소식"은 링크)를 보여 줘야 한다. (SOC-04)
- **FR-036**: 시스템은 이웃 추가·취소에 경험치·코인을 주지 않아야 한다. (SOC-04)

**마을 소식 (SOC-05)**

- **FR-037**: 시스템은 로그인 여부와 관계없이 누구나 마을 소식을 볼 수 있게 해야 하며, 광장 게시판의 마을 소식 입구로 들어간다. (SOC-05)
- **FR-038**: 시스템은 모든 블로그의 공개 글만 블로그 구분 없이 최신순(작성 시각, 같으면 나중 글 먼저)으로 한 페이지 8개씩 보여 줘야 한다. 글 주인이나 관리자가 봐도 비공개 글은 나오지 않는다. 전체 글 수는 보여 주지 않는다. (SOC-05)
- **FR-039**: 시스템은 카드마다 작성자 줄(캐릭터·닉네임·블로그 이름)을 보여 주고, 작성자 줄은 그 블로그 홈으로, 나머지는 글 상세로 이어져야 한다. 카드 날짜는 처음 쓴 날(한국 시간)이다. (SOC-05)
- **FR-040**: 시스템은 제목 `📋 마을 소식`, 브라우저 탭 제목 `마을 소식 | Blogville`, 그 아래 [🏘 마을 전체] [💛 이웃 새 글] 탭(지금 탭 강조, 이웃 탭은 온보딩을 마친 회원에게만)을 보여 줘야 한다. (SOC-05)
- **FR-041**: 시스템은 공개 글에 달린 태그만 세어 많이 달린 순(같으면 이름순)으로 최대 30개를 `#태그 N`으로 보여 줘야 하며, 태그가 없으면 `아직 태그가 없어요`를 보여 준다. 넓은 화면에서는 목록 옆, 좁은 화면에서는 목록 아래에 둔다. (SOC-05)
- **FR-042**: 시스템은 공개 글이 없으면 `아직 마을에 글이 없어요. 첫 글의 주인공이 되어 보세요! ✏️`를 보여 줘야 한다. (SOC-05)
- **FR-043**: 시스템은 페이지 번호가 1~2,147,483,647 정수가 아니면(`abc`, `0`, `2.5`, `1e300`, 아주 큰 수) 오류 없이 1페이지를 보여 주고, 페이지가 1개뿐이면 페이지 번호를 숨겨야 한다. (SOC-05)
- **FR-044**: 시스템은 글 발행·삭제, 공감, 댓글 변경이 마을 소식을 다시 열 때 바로 반영되도록 항상 최신 내용을 보여 줘야 한다. (SOC-05)
- **FR-045**: (알려진 문제) 마지막보다 큰 페이지를 열면 글이 있어도 `아직 마을에 글이 없어요. 첫 글의 주인공이 되어 보세요! ✏️`가 나오고, 현재 페이지 표시도 없다. 이웃 새 글도 같다. (SOC-05, SOC-04)

### Key Entities *(include if feature involves data)*

- **댓글**: 한 글에 달린 회원의 짧은 글. 작성자, 대상 글, 내용(1~1000자), 작성 시각, 삭제 시각(삭제 표시), 선택적 원댓글(답글일 때)을 가진다. 답글의 원댓글은 같은 글의 원댓글 하나뿐이다(1단계).
- **공감**: 한 회원이 한 글에 남긴 반응. 회원·글 쌍마다 최대 1개.
- **이웃 관계**: 한 회원(이웃을 맺는 사람)이 다른 회원(블로그 주인)을 따르는 방향 있는 관계. 회원 쌍마다 최대 1개, 자기 자신은 불가.
- **활동 보상 기록**: 댓글 작성(작성자에게)과 공감 받음(글 주인에게)으로 지급된 경험치·코인 기록. 하루 상한과 "같은 사람·같은 글 1번" 규칙을 판단하는 근거다 (게임 영역 GAME-05와 공유).
- **글 / 블로그 / 회원 프로필 / 태그**: 다른 영역에서 정의되며, 이 기능은 공개 여부·작성자·캐릭터·닉네임·블로그 이름·태그를 읽어 쓴다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 방문자를 포함한 누구나 로그인 없이 마을 소식을 열 수 있고, 어떤 계정으로 보아도 비공개 글이 0건 노출된다.
- **SC-002**: 회원은 글 상세에서 댓글 등록을 버튼 한 번으로 끝내고, 등록한 댓글이 새로고침 없이 목록에 나타난다.
- **SC-003**: 공감 버튼을 누르면 하트와 수가 즉시(체감 지연 없이) 바뀌고, 어떤 순서·동시성으로 눌러도 한 사람이 한 글에 남긴 공감은 최대 1개다.
- **SC-004**: 보상 규칙 위반이 0건이다: 댓글(답글 포함) 보상은 회원당 하루 10번, 공감 보상은 글 주인당 하루 20번, 같은 사람·같은 글 공감 보상은 1번을 넘지 않는다.
- **SC-005**: 작성자가 아닌 사람의 댓글 삭제 시도, 자기 자신·없는 회원 이웃 추가 시도, 비공개 글 대상 댓글·공감 시도가 100% 저장되지 않는다.
- **SC-006**: 범위를 벗어나거나 형식이 틀린 식별자·페이지 번호를 넣어도 서버 오류 화면이 0건이다(알려진 문제 FR-029 제외).
- **SC-007**: 이웃 추가 후 이웃 새 글에 그 블로그의 공개 글이 100% 나오고, 이웃 취소 후 0건 나온다.
- **SC-008**: 마을 소식·이웃 새 글·댓글 영역이 375px 너비에서 가로 스크롤 없이 쓸 수 있다.
- **SC-009**: 글 목록(마을 소식, 이웃 새 글) 화면이 1초 안에 표시된다.

## Assumptions

- 사용자는 방문자, 회원(온보딩 완료), 관리자 세 종류다. 로그인했지만 온보딩 전인 사용자는 교류 기능에서 방문자처럼 다룬다.
- "하루"는 한국 시간 0시 기준이다. 보상 수치와 상한은 게임 영역(GAME-05)의 규칙을 따른다.
- 글의 공개/비공개, 글 카드 모양·페이지 나누기(POST-05), 인기 태그(POST-04), 광장 게시판 입구(TOWN-03)는 다른 영역에서 정의되며 이 기능은 그대로 재사용한다.
- 보상은 회수하지 않는다: 댓글 삭제, 공감 취소, 글 삭제 후에도 이미 지급된 보상은 유지된다.
- 화면의 댓글 삭제는 내용만 지우는 "삭제 표시"이며, 댓글이 실제로 사라지는 것은 글이나 회원이 지워질 때뿐이다.
- 회원 탈퇴(AUTH-06)는 아직 없다. 회원이 지워지면 그 회원의 댓글·공감·이웃 관계가 함께 사라진다고 가정한다.
- 알림(댓글·공감·이웃 새 글 알림)은 없다. 보상은 헤더 코인 변화로만 드러난다.
- Out of scope: 이 영역에 `❌ 제외` 요구사항은 없다. 댓글 수정, 공감한 사람 목록, 이웃·팔로워 목록, 알림, 인기순 정렬, 마을 소식 내 검색은 이번 범위에 넣지 않는다.
- 검색은 광장·마을 소식이 아니라 내 블로그 안에서 한다는 방향이 결정되었다(BLOG-07, 미구현). 이 기능의 범위가 아니다. (SOC-05)
- 광장 헤더의 이동 메뉴는 없앴다(TOWN-01, 결정). 이웃 새 글은 마을 소식의 탭으로만, 마을 소식은 광장 게시판으로만 들어간다. (SOC-04, SOC-05)

### 원천 문서의 열린 질문

아래는 원천 문서에서 아직 정해지지 않은 질문이다. 정해질 때까지 **현재 동작을 유지하고 (제안)은 채택하지 않는다**. (위 [NEEDS CLARIFICATION] 3건은 제외)

- SOC-01: 댓글 수정 기능 → 없음 유지.
- SOC-01: 댓글이 많을 때 나눠 보여 주기 → 전부 표시 유지.
- SOC-01: 삭제한 댓글의 보상 회수 → 회수하지 않음.
- SOC-01: (제안) 블로그 관리에 내 글의 댓글 모아 보기·바로 삭제 → 채택하지 않음.
- SOC-01: 방문자가 `로그인`을 눌러 로그인하면 광장으로 감 → 보던 글로 돌아오지 않음 유지.
- SOC-01: ERD 문서의 삭제 문구(`삭제된 댓글입니다`)를 화면 문구로 맞출지 → 화면 문구 `삭제된 댓글이에요`가 기준.
- SOC-02: (제안) 잘못된 부모 지정을 `답글을 달 댓글이 없어요` / `답글에는 답글을 달 수 없어요`로 거부 → 채택하지 않음, 현재처럼 고쳐 저장.
- SOC-02: (제안) 삭제된 댓글에 대한 답글을 서버에서도 `삭제된 댓글에는 답글을 달 수 없어요`로 거부 → 채택하지 않음.
- SOC-02: (제안) 답글 입력칸 하나만 열기·자동 커서·답글 맨 아래에 열기 → 채택하지 않음.
- SOC-02: 답글 오류 문구를 `답글을 적어 주세요` / `답글은 1000자까지예요`로 바꾸고 영어 검증 문구를 우리말로 → 현재 문구 유지.
- SOC-02: 탈퇴 회원의 원댓글과 거기 달린 남의 답글 처리 → 탈퇴 기능 구현 때 결정. 현재는 함께 사라진다.
- SOC-02: 답글 등록·보상 시나리오의 자동 테스트 추가 → 미정.
- SOC-03: 내 글 공감 막기 → 허용 유지(수에 포함).
- SOC-03: 공감한 사람 목록 → 보여 주지 않음.
- SOC-03: (제안) 방문자가 누르면 안내 후 로그인 화면으로 보내고 돌아오기 → 채택하지 않음, 비활성 버튼 유지.
- SOC-03: 온보딩 전 회원에게 온보딩 안내 → 현재 `로그인하면 공감할 수 있어요` 유지.
- SOC-03: (제안) 저장되지 않은 공감에 `글을 찾을 수 없어요` 표시 → 채택하지 않음.
- SOC-03: (제안) 동시 첫 공감 충돌을 조용히 넘기기 → 채택하지 않음(알려진 문제 FR-029로 기록).
- SOC-03: (제안) 블로그 관리에서 받은 공감 합계 보기 → 채택하지 않음.
- SOC-03: 상한으로 보상받지 못한 공감이 다음 날 재공감 시 보상되는 동작 → 유지.
- SOC-04: (제안) 내 이웃 목록·나를 이웃 추가한 사람 목록, 목록에서 `이웃을 취소할까요?` 후 취소 → 채택하지 않음.
- SOC-04: 광장의 🏘 이웃집(최근 공개 글 블로그)과 이웃 기능의 관계·이름 혼동 → 현재 유지(TOWN-04와 함께 결정).
- SOC-04: 이웃 새 글 알림 → 없음.
- SOC-04: (제안) 빈 화면 문구를 `아직 이웃이 없어요.` / `이웃이 아직 글을 쓰지 않았어요.`로 나누기 → 채택하지 않음.
- SOC-04: (제안) 방문자에게도 [+ 이웃 추가]를 보여 주고 `이웃을 추가하려면 로그인하세요.` 안내 → 채택하지 않음.
- SOC-04: (제안) 처리 중 버튼 막기와 `{블로그 이름}을(를) 이웃으로 추가했어요.` / `이웃을 취소했어요.` 알림 → 채택하지 않음.
- SOC-05: 인기순 정렬 → 없음.
- SOC-05: (제안) 마을 소식 검색창 → 채택하지 않음(검색은 BLOG-07 방향).
- SOC-05: 비공개 → 공개로 바꾼 글의 정렬 기준 → 처음 쓴 시각 유지.
- SOC-05: 마지막보다 큰 페이지의 표시 → 현재 동작 유지(알려진 문제 FR-045로 기록).
- SOC-05: (제안) 1페이지 위 "블로그 둘러보기" 줄(12개) → 채택하지 않음.
