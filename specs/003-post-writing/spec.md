## Clarifications

### Session 2026-10-07

> 사용자가 결정을 Claude에게 맡겨, 아래 답은 원천 문서 맥락에 맞춰 정한 기본 결정이다. 팀 논의로 바뀔 수 있다.

- Q: 같은 사람(또는 같은 브라우저)이 같은 글을 다시 열 때 조회수를 또 셀까, 막는다면 기준은 24시간에 1번인가, 한국 시간 날짜 기준 하루 1번인가? → A: 막는다. 같은 사람은 한국 시간 날짜 기준 하루 1번만 센다. 온보딩을 마친 로그인 회원은 회원 기준, 로그인하지 않은 방문자와 온보딩 전 회원은 브라우저 식별값 기준이다(블로그 방문자 수 BLOG-06과 같은 기준). 글 작성자 본인이 열면 세지 않는다.
- Q: 비공개 글에 쓰인 사진·파일은 그 글을 볼 수 있는 사람(주인)에게만 열리게 막아야 하는가? → A: 막는다. 비공개 글에 쓰인 사진·파일은 그 글의 주인에게만 열리고, 다른 사람(방문자 포함)은 없는 주소와 같은 찾을 수 없음(404) 응답을 받는다. 공개 글 첨부는 지금처럼 누구나 연다. 글이 공개 ↔ 비공개로 바뀌면 접근도 바로 바뀐다. 아직 어느 글에도 쓰이지 않은 첨부는 올린 사람에게만 열린다.
- Q: 쓰던 새 글의 임시 글을 그 브라우저에만 저장할까, 서비스(서버)에 저장해 어느 기기에서나 복구할 수 있게 할까? → A: 그 브라우저에만 저장한다(회원별 1개, 새 글에만, 발행 성공 시 삭제). 다른 기기·브라우저에서는 복구되지 않으며, 데이터 구조는 바뀌지 않는다.

## User Scenarios & Testing *(mandatory)*

BlogCabin은 글쓰기가 제품의 중심이다. 회원은 내 블로그(광장의 내 집)에서 [✏️ 글쓰기]로 글을 쓰고, 발행하면 경험치·코인을 받는다. 글은 공개/비공개, 카테고리, 태그로 정리되고, 마을의 여러 목록에서 다른 사람에게 발견된다. 사진과 파일을 함께 올릴 수 있다.

### User Story 1 - 글을 써서 발행하기 (Priority: P1)

온보딩을 마친 회원이 내 블로그 홈의 [✏️ 글쓰기](글이 없으면 [첫 글 쓰기])로 글쓰기 화면에 들어가 제목·본문을 쓰고 [발행하기]를 누른다. 본문은 서식 도구(큰 제목·작은 제목, 굵게·기울임·밑줄·취소선, 글머리·번호 목록, 인용, 코드 블록, 구분선, 링크, 되돌리기·다시 실행)로 꾸밀 수 있다. 쓰는 동안 아래 상자에 글자 수와 보상 안내가 실시간으로 바뀌고, 발행하면 그 글 상세 화면으로 이동해 발행 안내를 본다.

**Why this priority**: 글쓰기가 제품의 핵심 가치이자 게임 보상의 출발점이다. 이것만 있어도 블로그로서 쓸 수 있다.

**Independent Test**: 회원으로 로그인해 제목과 100자 이상 본문을 쓰고 발행하면, 글 상세로 이동해 서식이 그대로 보이고 보상 안내가 뜨는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 온보딩을 마친 회원이 글쓰기 화면에 있고, **When** 제목과 본문을 쓰고 [발행하기]를 누르면, **Then** 글이 저장되고 그 글 상세 화면으로 이동해 맨 위에 발행 안내가 보인다.
2. **Given** 오늘 글쓰기 보상을 3번 미만 받은 회원이 새 공개 글에 본문 100자 이상을 썼고, **When** 발행하면, **Then** `🎉 글을 발행했어요! ✨ 경험치 30 · 🪙 30 코인을 받았어요`가 보인다.
3. **Given** 비공개 글, 100자 미만 글, 또는 오늘 보상 3번을 다 받은 상태이고, **When** 발행하면, **Then** `🎉 글을 발행했어요! (비공개 글, 짧은 글, 또는 오늘 글쓰기 보상 3번을 다 받아서 보상은 없어요)`가 보인다.
4. **Given** 본문에 굵게·제목·목록·인용·코드·링크를 썼고, **When** 발행하면, **Then** 글 상세에서 같은 서식으로 보인다.
5. **Given** 두 문단 49자 + 50자를 썼고, **When** 아래 상자를 보면, **Then** `100자 · 저장하면 ✨ 경험치 30 · 🪙 30 보상 (하루 3번까지)`가 보이고 발행하면 (하루 상한 안이면) 보상을 받는다.
6. **Given** 한 문단 50자 + 문단을 나누지 않는 줄바꿈 + 49자를 썼고, **When** 아래 상자를 보면, **Then** `99자 · 100자 이상 쓰면 보상을 받아요`가 보이고 발행해도 보상이 없다.
7. **Given** 제목·카테고리·태그를 쓰고 본문은 비웠고, **When** [발행하기]를 누르면, **Then** `본문을 적어 주세요`가 보이고 제목·카테고리·태그·본문·공개 설정은 입력한 그대로 남는다.
8. **Given** 본문에 위험한 HTML(스크립트, 이벤트 속성, `javascript:` 링크 등)을 섞어 보냈고, **When** 저장되면, **Then** 저장된 본문에 그 요소가 남지 않는다.
9. **Given** 본문이 비어 있고, **When** 글쓰기 화면을 열면, **Then** 첫 줄에 `오늘 배운 것, 생각한 것, 무엇이든 적어 보세요 ✏️`가 흐리게 보이고, 글자를 쓰면 사라진다.
10. **Given** 로그인하지 않은 사람이, **When** 글쓰기 화면 주소로 들어가면, **Then** 첫 화면으로 이동한다.

### User Story 2 - 내 글 고치기와 지우기 (Priority: P2)

글쓴이가 내 글 상세의 [수정]으로 저장된 내용이 채워진 같은 화면을 열어 고치고 [수정 완료]를 누른다. [삭제]를 누르면 확인 창을 거쳐 글을 지운다.

**Why this priority**: 쓴 글을 바로잡거나 지울 수 없으면 글쓰기를 믿고 쓰기 어렵다. 다만 발행 자체보다는 뒤에 필요하다.

**Independent Test**: 글 하나를 발행한 뒤 수정해 내용이 바뀌는지, 목록 순서·작성 시각이 그대로인지, 삭제하면 댓글·공감과 함께 사라지는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 내 글 상세 화면이고, **When** [수정]을 누르면, **Then** 제목·카테고리·공개 설정·본문·태그가 저장된 대로 채워진 화면이 열리고 버튼은 [수정 완료]다.
2. **Given** 수정 화면에서 내용을 바꿨고, **When** [수정 완료]를 누르면, **Then** 글 상세로 돌아가고 보상과 발행 안내는 없으며 작성 시각과 목록 순서는 그대로다.
3. **Given** 내 글 상세 화면이고, **When** [삭제]를 누르면, **Then** `이 글을 삭제할까요? 댓글과 공감도 함께 지워져요.` 확인 창이 뜬다.
4. **Given** 삭제 확인 창에서, **When** 확인하면, **Then** 안내 없이 내 블로그 홈으로 이동하고 글과 그 글의 댓글·공감이 함께 지워진다. [취소]를 누르면 아무 일도 없다.
5. **Given** 다른 회원의 글 상세이고, **When** 화면을 보면, **Then** [수정] [삭제]가 보이지 않는다.
6. **Given** 남의 글·없는 글·허용 범위 밖 번호의 수정 화면 주소이고, **When** 들어가면, **Then** 찾을 수 없음(404) 화면이 나온다.
7. **Given** 남의 글 번호로 수정 요청을 조작해 보냈고, **When** 처리되면, **Then** 아무것도 저장되지 않고 🚧 `잠깐 문제가 생겼어요` / [다시 시도] [광장으로 돌아가기] 오류 화면이 뜬다.
8. **Given** 남의 글 번호나 허용 범위 밖 번호로 삭제 요청을 조작해 보냈고, **When** 처리되면, **Then** 아무것도 지워지지 않는다.

### User Story 3 - 공개 / 비공개 정하기 (Priority: P2)

글쓴이가 글마다 [🌍 공개] 또는 [🔒 비공개]를 고른다. 비공개 글은 주인만 볼 수 있고, 다른 사람의 목록과 집계에서 빠진다.

**Why this priority**: 개인적인 기록을 안심하고 남길 수 있게 하는 기본 기능이며, 보상·목록·공감·댓글 규칙이 모두 이 값에 기대고 있다.

**Independent Test**: 비공개 글을 발행한 뒤 다른 회원·방문자로 목록과 주소를 열어 보이지 않는지, 주인에게는 `🔒 비공개` 표시와 함께 보이는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 새 글쓰기 화면이고, **When** 화면을 열면, **Then** [🌍 공개]가 골라져 있다. 수정 화면은 저장된 값이 골라져 있다.
2. **Given** 새 글에서 [🔒 비공개]를 골랐고, **When** 아래 상자를 보면, **Then** `N자 · 비공개 글은 보상이 없어요`가 보이고, 100자 이상으로 발행해도 보상이 없다.
3. **Given** 비공개 글이 있고, **When** 다른 회원·방문자·관리자가 그 글 주소로 들어가면, **Then** 🧭 `길을 잃었어요` / `찾는 블로그나 글이 없거나, 비공개 글이에요.` / [광장으로 돌아가기] 화면이 나온다.
4. **Given** 비공개 글이 있고, **When** 다른 사람이 블로그 홈·마을 소식·이웃 새 글·태그별 글·이전/다음 글·인기 태그를 보면, **Then** 그 글은 어디에도 나오지 않는다.
5. **Given** 주인이 내 블로그 홈을 보고, **When** 목록을 보면, **Then** 비공개 글이 `🔒 비공개` 배지와 함께 나오고 이전/다음 글에도 나온다.
6. **Given** 공개 글을 비공개로 바꿨다가 다시 공개로 바꿨고, **When** 저장하면, **Then** 글 보상은 새로 들어오지 않는다.
7. **Given** 다른 사람이 비공개 글에 공감·댓글을 조작해 보냈고, **When** 처리되면, **Then** 공감은 저장되지 않고 댓글은 `글을 찾을 수 없어요`로 거부된다.

### User Story 4 - 글 목록 둘러보기 (Priority: P2)

방문자와 회원이 블로그 홈, 마을 소식, 이웃 새 글, 태그별 글에서 최신순 카드 목록을 페이지 단위로 본다.

**Why this priority**: 쓴 글이 읽히는 통로이며, 다른 블로그를 발견하게 하는 목표와 직결된다.

**Independent Test**: 글 9개를 만든 뒤 1페이지 8개·2페이지 1개, 최신순, 카드 구성, 페이지 번호 표시를 확인한다.

**Acceptance Scenarios**:

1. **Given** 조건에 맞는 글이 9개이고, **When** 목록을 열면, **Then** 1페이지에 8개, 2페이지에 1개가 보인다.
2. **Given** 같은 시각에 쓴 글이 둘이고, **When** 목록을 보면, **Then** 나중에 쓴 글이 먼저 보인다.
3. **Given** 20페이지 중 10페이지이고, **When** 페이지 번호를 보면, **Then** `1 … 8 9 10 11 12 … 20`으로 보이고 10만 현재 페이지로 강조된다.
4. **Given** 글이 8개 이하이고, **When** 목록을 보면, **Then** 페이지 번호가 보이지 않는다.
5. **Given** 페이지 값이 `0`, `abc`, `2.5`, 아주 큰 수이고, **When** 목록을 열면, **Then** 오류 없이 1페이지가 보인다.
6. **Given** 블로그 홈에서 카테고리를 골랐고, **When** 2페이지로 가면, **Then** 그 카테고리 글만 보인다.
7. **Given** 마을 소식·이웃 새 글·태그별 글이고, **When** 카드를 보면, **Then** 카드 위에 작성자 줄이 있고, 블로그 홈 카드에는 없다.
8. **Given** 로그인하지 않은 사람이, **When** 이웃 새 글에 들어가면, **Then** 첫 화면으로 이동한다.

### User Story 5 - 카테고리와 태그로 정리하고 모아보기 (Priority: P3)

글쓴이가 글에 내 블로그 카테고리 하나와 태그 여러 개를 단다. 읽는 사람은 글 상세의 카테고리 배지·태그를 눌러 같은 분류의 글을 모아 보고, 인기 태그에서 마을 전체의 관심사를 본다.

**Why this priority**: 글이 쌓일수록 가치가 커지는 정리·발견 기능이지만, 없어도 글쓰기와 읽기는 된다.

**Independent Test**: 카테고리와 `git, #회고, Git` 태그로 글을 발행한 뒤 배지·태그 2개가 보이고, 각각을 눌러 해당 목록으로 가는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 새 글쓰기 화면이고, **When** 카테고리 선택을 보면, **Then** `카테고리 없음`이 골라져 있고 그 아래 내 블로그 카테고리만 블로그에서 정한 순서대로 나온다.
2. **Given** 카테고리를 고르지 않고 발행했고, **When** 목록 카드와 글 상세를 보면, **Then** 카테고리 배지가 없다.
3. **Given** 글 상세에 카테고리 배지가 있고, **When** 배지를 누르면, **Then** 그 블로그의 그 카테고리 글 목록으로 간다.
4. **Given** 다른 블로그의 카테고리나 쓰는 사이 지워진 카테고리를 보냈고, **When** 저장되면, **Then** 오류 없이 `카테고리 없음`으로 저장된다.
5. **Given** 태그 칸에 `git, #회고, Git`을 적었고, **When** 저장하면, **Then** `#git` `#회고` 2개만 달린다.
6. **Given** 21자 태그와 규칙에 맞는 태그 11개를 적었고, **When** 저장하면, **Then** 21자 태그는 빠지고 앞의 10개만 저장된다.
7. **Given** 태그가 달린 글을 수정해 태그 칸을 비웠고, **When** 저장하면, **Then** 그 글의 태그가 모두 없어진다.
8. **Given** 로그인하지 않은 방문자가, **When** 공개 글이 없는 태그 주소를 열면, **Then** `이 태그가 달린 글이 없어요.`가 보인다.
9. **Given** 마을 소식 화면이고, **When** 인기 태그를 보면, **Then** 공개 글에 많이 쓰인 순 → 같으면 이름순으로 최대 30개가 `#태그 N` 형식으로 보인다.

### User Story 6 - 조회수 보기 (Priority: P3)

블로그 주인이 아닌 사람이 글 상세를 열면 같은 사람은 한국 시간 날짜 기준 하루 1번만 조회수가 오르고, 글 상세와 목록 카드에 `👀 N`으로 보인다.

**Why this priority**: 글쓴이에게 읽히고 있다는 동기를 주지만, 핵심 흐름에는 필요하지 않다.

**Independent Test**: 다른 회원으로 글 상세를 열어 숫자가 1 오르는지, 같은 날 다시 열면 그대로인지, 주인으로 열면 그대로인지 확인한다.

**Acceptance Scenarios**:

1. **Given** 주인이 아닌 사람(방문자·관리자 포함)이 오늘(한국 시간) 그 글을 처음 열고, **When** 글 상세를 열면, **Then** 조회수가 1 오르고 그 화면의 `👀 N`에 바로 반영된다.
2. **Given** 주인이, **When** 자기 글을 열면, **Then** 조회수가 오르지 않는다.
3. **Given** 찾을 수 없음 화면이 나는 주소(없는 블로그·글, 잘못된 번호, 다른 블로그 주소, 남의 비공개 글)이고, **When** 열면, **Then** 조회수가 오르지 않는다.
4. **Given** 조회수가 올랐고, **When** 글의 수정 시각을 확인하면, **Then** 수정 시각은 바뀌지 않는다.
5. **Given** 오늘 이미 그 글을 연 사람이, **When** 같은 날 다시 열거나 새로고침하면, **Then** 조회수가 오르지 않는다.
6. **Given** 어제 그 글을 연 사람이, **When** 한국 시간 0시가 지난 뒤 다시 열면, **Then** 조회수가 1 오른다.
7. **Given** 로그인한 회원이 오늘 휴대폰에서 그 글을 열었고, **When** 같은 날 PC에서 같은 회원으로 열면, **Then** 조회수가 오르지 않는다.
8. **Given** 로그인하지 않은 방문자가 오늘 한 브라우저에서 그 글을 열었고, **When** 같은 날 다른 브라우저(또는 시크릿 창)에서 열면, **Then** 새 사람으로 보고 조회수가 1 오른다.

### User Story 7 - 사진과 파일 첨부하기 (Priority: P4)

글쓴이가 [🖼 사진]·[📎 파일] 버튼, 붙여 넣기, 끌어다 놓기로 여러 개를 한 번에 본문에 넣는다. 사진은 본문 폭에 맞춰 보이고, 파일은 카드로 보여 누르면 원래 이름으로 내려받는다.

**Why this priority**: 글을 풍부하게 하지만 글자만으로도 블로그는 동작한다 (우선순위 C).

**Independent Test**: 사진 두 장과 PDF·HWP 파일 하나씩을 넣고 발행한 뒤, 상세에서 사진이 보이고 파일 카드를 누르면 원래 이름으로 내려받는지 확인한다. 같은 글을 비공개로 바꾸면 다른 사람에게는 그 사진·파일 주소가 찾을 수 없음으로 나오는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 글쓰기 화면이고, **When** [🖼 사진]으로 두 장을 한 번에 고르면, **Then** 둘 다 본문에 들어간다. 붙여 넣기로도 들어간다.
2. **Given** 올리는 중이고, **When** 화면을 보면, **Then** `올리는 중... (1/3)`이 보이고 첨부 버튼은 눌리지 않으며 발행 버튼은 `첨부를 올리는 중...`으로 바뀌어 눌리지 않는다.
3. **Given** 확장자만 `.png`인 SVG를 골랐고, **When** 올리면, **Then** `사진 파일이 아니에요. PNG·JPG·GIF·WEBP 사진만 올릴 수 있어요`로 거부되고 본문에 들어가지 않는다.
4. **Given** 10MB가 넘는 사진을 골랐고, **When** 올리면, **Then** `사진은 10MB까지 올릴 수 있어요`로 거부된다.
5. **Given** 사진이 든 글을 발행했고, **When** 글 상세와 수정 화면을 열면, **Then** 사진이 보이고 에디터에도 그대로 있다.
6. **Given** PDF·HWP 파일 두 개를 끌어다 놓았고, **When** 올라가면, **Then** 파일 카드 두 개가 들어가고 글 상세에 원래 이름과 크기가 보인다.
7. **Given** 글 상세의 파일 카드이고, **When** 누르면, **Then** 원래 이름(예: `보고서 최종본.pdf`)으로 올린 내용 그대로 내려받는다.
8. **Given** EXE 파일을 골랐고, **When** 올리면, **Then** `올릴 수 없는 형식이에요. 사진은 PNG·JPG·GIF·WEBP, 파일은 PDF·한글·워드·엑셀·파워포인트·키노트·ZIP·TXT·CSV·MD·JSON·MP3·MP4만 올릴 수 있어요`로 거부된다.
9. **Given** 로그인하지 않았거나 다른 사이트에서 올리기 요청을 보냈고, **When** 처리되면, **Then** 저장되지 않는다.
10. **Given** 사진·파일 카드가 든 글이고, **When** 보상 글자 수를 세면, **Then** 사진·파일 카드는 글자 수에 들어가지 않는다.
11. **Given** 비공개 글에 사진·파일이 들어 있고, **When** 주인이 아닌 사람(방문자·다른 회원·관리자)이 그 사진·파일 주소를 직접 열면, **Then** 없는 주소와 같은 `파일을 찾을 수 없어요` 찾을 수 없음 응답을 받는다. 주인은 그대로 보고 내려받는다.
12. **Given** 사진이 든 공개 글을 비공개로 바꿨고, **When** 다른 사람이 그 사진 주소를 열면, **Then** 바로 찾을 수 없음 응답을 받고, 다시 공개로 바꾸면 바로 열린다.
13. **Given** 글쓰기 화면에서 올렸지만 아직 어느 글에도 쓰이지 않은 사진이고, **When** 올린 사람이 아닌 사람이 그 주소를 열면, **Then** 찾을 수 없음 응답을 받는다. 올린 사람은 에디터에서 그대로 본다.

### User Story 8 - 쓰던 새 글 임시 저장 (Priority: P5)

회원이 새 글을 쓰다가 새로고침·탭 닫기·다른 화면 이동·로그인 만료로 화면을 벗어나도, 같은 브라우저에서 다시 글쓰기 화면을 열면 쓰던 내용을 불러올 수 있다. 임시 글은 그 브라우저에만 저장되어 다른 기기나 다른 브라우저에서는 불러올 수 없다. (미구현 ⬜)

**Why this priority**: 글을 잃는 불편을 줄이지만 우선순위 C이고 아직 구현되지 않았다.

**Independent Test**: 새 글에 제목·본문을 쓰고 입력을 멈춘 뒤 새로고침해서 불러오기를 고르면 모든 칸이 채워지는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 새 글에 제목과 본문을 쓰고 입력을 2초 멈췄고, **When** 새로고침해서 불러오기를 고르면, **Then** 제목·카테고리·공개 설정·본문(서식 포함)·태그가 그대로 채워진다.
2. **Given** 입력을 멈추고 2초가 지났고, **When** 아래 상자를 보면, **Then** 마지막 저장 시각(시:분, 한국 시간)이 보인다.
3. **Given** 임시 글이 있고, **When** 불러오지 않기를 고르면, **Then** 빈 글쓰기 화면이 열린다.
4. **Given** 제목·본문을 비운 채 카테고리만 바꿨고, **When** 2초 뒤 새로고침하면, **Then** 불러올지 묻지 않는다.
5. **Given** 발행에 성공했고, **When** 글쓰기 화면을 다시 열면, **Then** 불러올지 묻지 않는다 (마지막 입력 뒤 2초 안에 발행해도 같다).
6. **Given** 발행이 오류로 실패했고, **When** 임시 글을 확인하면, **Then** 임시 글이 남아 있다.
7. **Given** 회원 A의 임시 글이 있고, **When** 같은 환경에서 회원 B로 로그인하면, **Then** A의 임시 글은 보이지 않는다.
8. **Given** 브라우저의 임시 저장 공간을 쓸 수 없고, **When** 글을 쓰고 발행하면, **Then** 글쓰기·발행은 정상이고 오류가 뜨지 않는다.
9. **Given** 글 수정 화면이고, **When** 글을 고치면, **Then** 임시 저장도, 불러오기 질문도 없다.
10. **Given** 한 브라우저에 회원 A의 임시 글이 있고, **When** A가 다른 기기나 다른 브라우저에서 글쓰기 화면을 열면, **Then** 불러올지 묻지 않고 빈 글쓰기 화면이 열린다.

### Edge Cases

- 쓰는 동안 로그인이 풀린 채 [발행하기]를 누르면 첫 화면으로 이동한다. POST-08 전까지는 쓰던 글이 사라지고, POST-08 뒤에는 같은 브라우저에서 같은 회원으로 다시 로그인해 글쓰기 화면을 열면 마지막 임시 저장 내용을 불러올 수 있다.
- 제목이 완전히 비어 있으면 화면이 먼저 막고, 공백만 적으면 `제목을 적어 주세요`가 보인다.
- 본문에 빈 줄·구분선만 있으면 `본문을 적어 주세요`, 사진만 있고 글자가 없어도 `본문을 적어 주세요`가 보인다.
- 오류는 한 번에 하나(검사 순서상 첫 번째)만 보이고, 입력값은 모두 남는다.
- 글 번호·카테고리 번호를 허용 범위(2,147,483,647)보다 크게 조작하면 `잘못된 요청이에요`가 보이고 저장되지 않으며 제목·본문·태그는 남는다.
- 공개 설정이나 카테고리에 규칙 밖 값(`0`, `abc`, `1.5` 등)을 조작해 보내면 저장되지 않는다. 지금은 정해진 한국어 문구가 없다 (열린 질문).
- 본문이 매우 길어 요청 자체가 처리 한도(약 1MB, 한글만 약 35만 자)를 넘으면 `글이 너무 길어요`가 나오기 전에 요청이 거절된다 (열린 질문).
- 블로그에 카테고리가 하나도 없으면 선택지는 `카테고리 없음` 하나뿐이고 안내 없이 저장된다.
- 글의 카테고리가 나중에 지워지면 글은 남고 배지만 사라진다.
- `c#`처럼 `#`이 든 태그는 `#`에서 나뉘어 `c`로 저장된다. 공백은 구분자가 아니어서 `git 회고`는 태그 하나다.
- 대문자 태그 주소(`Git`)로 열면 `git` 글이 있어도 `이 태그가 달린 글이 없어요.`가 보인다.
- `%`가 든 태그(예: `100%`)도 목록과 탭 제목 `#100% | BlogCabin`이 정상으로 보인다.
- 마지막 페이지보다 큰 번호로 열면 글이 있는데도 빈 화면 문구가 나오고 현재 페이지 표시가 없다.
- 공개 → 비공개로 바꿔도 이미 달린 댓글·공감·이미 받은 보상은 그대로 남지만 다른 사람에게는 보이지 않는다.
- 글을 보던 중 주인이 비공개로 바꾸면 그 뒤의 공감은 조용히 무시되고 댓글·답글은 `글을 찾을 수 없어요`가 보인다.
- 관리자가 관리 화면 "최근 30일 글"에서 남의 비공개 글 제목을 누르면 찾을 수 없음 화면이 나온다 (삭제는 된다).
- 여러 첨부 중 일부만 문제면 문제없는 것은 들어가고 문제 있는 것만 `파일 이름: 문구`로 남으며 [✕]로 닫는다.
- 올리는 중에 다른 파일을 넣으면 `다른 파일을 올리는 중이에요. 끝난 뒤 다시 넣어 주세요`가 보인다.
- 파일을 에디터 밖에 떨어뜨리면 아무 일도 없다 (쓰던 글을 잃지 않는다).
- 글자와 그림을 함께 복사해 붙여 넣으면 글자만 들어가고, 다른 사이트 사진이 든 내용을 붙여 넣으면 그 사진은 들어가지 않는다.
- 다른 회원이 올린 첨부 주소를 본문에 넣으면 그대로 남는다 (올린 사람은 확인하지 않는다). 그 첨부를 열 수 있는 사람은 FR-059에 따라 그 첨부가 쓰인 글의 공개 설정으로 정해진다.
- 비공개 글의 사진·파일 주소를 다른 사람에게 보내도 열리지 않는다 (찾을 수 없음). 로그인이 풀린 주인도 다른 사람과 같다.
- 같은 사람이 같은 날 같은 글을 여러 번 열어도 조회수는 1만 오른다. 다만 브라우저 데이터를 지우거나 시크릿 창·다른 브라우저로 연 방문자는 새 사람으로 센다 (막지 않음). 식별값이 없는 브라우저가 두 탭에서 거의 동시에 처음 열면 2번 셀 수 있다 (막지 않음).
- 같은 브라우저의 새 글 탭 두 개에서 동시에 쓰면 마지막에 임시 저장한 탭의 내용만 남는다 (POST-08).
- 임시 글은 그 브라우저에만 있으므로 다른 기기·다른 브라우저에서는 불러올 수 없고, 브라우저 데이터를 지우면 함께 사라진다. 한 브라우저에서 발행해도 다른 브라우저에 남은 임시 글은 지워지지 않는다 (POST-08).

**작성·수정·삭제 (POST-01)**

- **FR-043**: 페이지 값이 없거나 숫자만 적힌 1~2,147,483,647 정수가 아니면(`0`, `-1`, `abc`, `2.5`, `012`, `1e1`, 아주 큰 수) 오류 없이 1페이지를 보여야 한다. 블로그 홈의 카테고리 값이 그런 값이면 전체 글을 보여야 한다. (POST-05)
- **FR-044**: 글이 없으면 페이지 번호를 숨기고 화면별 문구를 보여야 한다: 블로그 홈 `🌱` `아직 글이 없어요.` (+주인에게만 [첫 글 쓰기]), 마을 소식 `아직 마을에 글이 없어요. 첫 글의 주인공이 되어 보세요! ✏️`, 이웃 새 글 `아직 이웃이 없거나 이웃의 새 글이 없어요.` / `마을 소식에서 마음에 드는 블로그를 이웃으로 추가해 보세요.`, 태그별 글 `이 태그가 달린 글이 없어요.` (POST-05)
- **FR-045**: 로그인하지 않고 이웃 새 글에 들어가면 첫 화면으로, 온보딩 전이면 온보딩 화면으로 보내야 한다. (POST-05)

**조회수 (POST-06)**

- **FR-046**: 블로그 주인이 아닌 사람(방문자, 다른 회원, 관리자, 로그아웃한 주인)이 글 상세를 열면 FR-048 기준으로 그날 처음 연 경우에만 조회수를 1 올리고, 그 화면에는 방금 센 것까지 더한 값을 보여야 한다. 주인이 열면 오르지 않는다. 여러 사람이 동시에 열어도 빠지는 수가 없어야 한다. (POST-06)
- **FR-047**: 찾을 수 없음 화면이 나는 주소(없는 블로그·글, 잘못된 번호, 다른 블로그 주소, 남의 비공개 글)에서는 조회수를 올리지 않아야 하며, 조회수가 올라도 글의 수정 시각은 바뀌지 않아야 한다. (POST-06)
- **FR-048**: 시스템은 같은 사람의 반복 조회를 막아야 한다. 한 글에서 같은 사람은 한국 시간 날짜 기준 하루 1번만 세고(0시에 새 날), 같은 날 다시 열거나 새로고침하면 조회수를 올리지 않아야 한다. 같은 사람의 기준은 블로그 방문자 수(BLOG-06)와 같다: 온보딩을 마친 로그인 회원은 회원 기준(기기·브라우저가 달라도 한 사람), 로그인하지 않은 방문자와 온보딩 전 회원은 브라우저 식별값 기준이다. 브라우저 데이터를 지우거나 시크릿 창·다른 브라우저로 연 방문자는 새 사람으로 센다(막지 않음). (POST-06)
- **FR-049**: 글 상세에서 공감·댓글을 해도 조회수가 오르지 않아야 한다. 공감·댓글 뒤 화면을 다시 그리는 것은 같은 사람이 같은 날 다시 연 것이므로 FR-048에 따라 세지 않는다. (POST-06)

**사진 첨부 (POST-07)**

- **FR-050**: 글쓴이는 [🖼 사진] 버튼, 붙여 넣기, 끌어다 놓기로 사진 여러 장을 한 번에 넣을 수 있어야 한다. 사진은 커서(또는 놓은) 위치에 올린 순서대로 들어가고, 커서는 마지막 사진 뒤로 옮겨지며, 올리는 동안 글을 고쳐도 넣을 자리가 따라가야 한다. (POST-07)
- **FR-051**: 사진은 PNG·JPG·GIF·WEBP, 한 장 10MB까지만 받아야 하며, 시스템은 확장자뿐 아니라 파일 내용으로 실제 형식을 다시 확인해야 한다. SVG는 받지 않는다. 문구: 받지 않는 형식 `올릴 수 없는 형식이에요. 사진은 PNG·JPG·GIF·WEBP, 파일은 PDF·한글·워드·엑셀·파워포인트·키노트·ZIP·TXT·CSV·MD·JSON·MP3·MP4만 올릴 수 있어요`, 크기 초과 `사진은 10MB까지 올릴 수 있어요`, 내용이 사진이 아님(확장자와 실제 형식이 다른 경우 포함) `사진 파일이 아니에요. PNG·JPG·GIF·WEBP 사진만 올릴 수 있어요`, 빈 파일 `빈 파일은 올릴 수 없어요`, 네트워크·저장 오류 `올리지 못했어요. 다시 시도해 주세요`. 문구는 도구 모음 아래 `파일 이름: 문구` 형식이다. (POST-07)
- **FR-052**: 올리는 동안 `올리는 중... (n/전체)`를 보여주고 첨부 버튼과 발행 버튼(`첨부를 올리는 중...`)을 막아야 하며, 그동안 들어온 다른 파일은 넣지 않고 `다른 파일을 올리는 중이에요. 끝난 뒤 다시 넣어 주세요`를 보여야 한다. 일부만 문제면 나머지는 들어가고 문제 문구만 남아 [✕]로 닫을 수 있어야 한다. (POST-07)
- **FR-053**: 올리기 요청은 온보딩을 마친 회원(`로그인한 회원만 올릴 수 있어요`)이 이 사이트에서 보낸 것(`잘못된 요청이에요`)만 받아야 하며, 크기를 밝히지 않은 요청과 허용 크기를 넘는 요청은 내용을 읽기 전에 거절해야 한다. (POST-07, POST-09)
- **FR-054**: 저장 파일 이름은 시스템이 무작위로 새로 만들고, 올린 파일 이름은 주소에 쓰지 않아야 한다. 본문에는 파일 내용을 직접 넣지 않고 우리 저장소 주소만 넣어야 한다. (POST-07)
- **FR-055**: 저장할 때 사진은 우리 저장소에 실제로 올라간 사진 주소만 남기고(대체 글 외 속성 제거), 다른 사이트·내장 데이터·스크립트 주소나 올린 적 없는 주소의 사진은 빼야 한다. 다른 사이트 사진이 든 내용을 붙여 넣으면 에디터에도 들어가지 않아야 한다. (POST-07, NF-03)
- **FR-056**: 사진 주소는 실제 형식으로, 내용 추측 실행을 막는 방식으로 제공되어야 하고, 없는 주소와 FR-059로 막힌 주소는 똑같이 `파일을 찾을 수 없어요`로 응답해야 한다. 본문 폭보다 큰 사진은 폭에 맞춰 줄이고 모서리를 둥글게 하며, 375px에서도 가로 스크롤이 없어야 한다. (POST-07, NF-06)
- **FR-057**: 파일을 에디터 밖에 떨어뜨리면 아무 일도 없어야 하고, 글자와 그림이 함께 복사된 내용을 붙여 넣으면 글자를 붙여 넣어야 한다. (POST-07)
- **FR-058**: 쓰이지 않게 된 첨부(글에서 지운 사진, 저장하지 않은 글의 사진·파일)를 정리해야 한다. (알려진 문제: 지금은 정리하지 않아 쌓인다. 방식은 열린 질문) (POST-07, POST-09)
- **FR-059**: 사진·파일 주소는 그 첨부가 쓰인 글의 공개 설정에 따라 열려야 한다. 공개 글에 쓰인 첨부는 누구나(로그인 없이) 열 수 있다. 비공개 글에 쓰인 첨부는 그 글의 주인에게만 열리고, 다른 사람(방문자·다른 회원·관리자)에게는 없는 주소와 똑같은 찾을 수 없음(404) 응답(`파일을 찾을 수 없어요`)을 주어 첨부가 있는지도 알리지 않아야 한다. 글이 공개 ↔ 비공개로 바뀌면 접근도 바로 바뀌어야 한다. 어느 글에도 쓰이지 않은 첨부(발행 전, 글에서 빠졌거나 글이 지워진 경우 포함)는 올린 사람에게만 열려야 한다. 여러 글에 쓰인 첨부는 그중 하나라도 공개 글이면 누구나 열 수 있다. (POST-07, POST-09)

**파일 첨부 (POST-09)**

- **FR-060**: 글쓴이는 [📎 파일] 버튼, 붙여 넣기, 끌어다 놓기로 PDF, 한글(HWP·HWPX), 워드(DOC·DOCX), 엑셀(XLS·XLSX), 파워포인트(PPT·PPTX), 키노트(KEY), ZIP, TXT, CSV, MD, JSON, MP3, MP4 파일을 한 개 30MB까지 여러 개 넣을 수 있어야 한다. 사진 파일은 사진으로 들어간다. 다른 형식은 FR-051의 형식 문구로, 30MB 초과는 `파일은 30MB까지 올릴 수 있어요`로 거부해야 한다. (POST-09)
- **FR-061**: 본문에 파일 카드(형식별 아이콘, 원래 이름, `크기 · 내려받기`; 크기는 `45B` / `340KB` / `1.2MB` 형식)를 넣고, 글 상세에서 누르면 올린 사람이 붙인 원래 이름(한글 포함)으로 내려받아야 한다. 에디터에서는 눌러도 내려받지 않고 선택·삭제·이동만 된다. 화면 낭독기는 `원래 이름 내려받기 (크기)`를 읽어야 한다. (POST-09)
- **FR-062**: 원래 이름은 경로 구분자와 제어 문자를 빼고 255자를 넘으면 확장자를 남기고 줄여야 한다. 저장할 때 파일 카드의 이름·크기는 실제 올라간 원래 값으로 다시 써야 하고, 다른 주소이거나 올린 적 없는 파일 카드는 빼야 한다. (POST-09, NF-03)

**임시 저장 (POST-08, 미구현)**

- **FR-063**: 시스템은 새 글의 제목·카테고리·공개 설정·본문·태그 중 하나라도 바뀐 뒤 입력이 2초 멈추면 그 내용을 회원별로 1개만(덮어쓰기) 임시 저장해야 한다. 임시 글은 지금 쓰는 그 브라우저에만 저장하고 서비스 쪽에는 저장하지 않으므로, 같은 브라우저에서만 불러올 수 있고 다른 기기·다른 브라우저에서는 복구되지 않는다. (POST-08)
- **FR-064**: 제목(앞뒤 공백 제거)과 본문 글자 수가 모두 0이면 임시 저장하지 않아야 한다. 임시 글에는 길이 제한을 두지 않고, 발행할 때 FR-007·FR-009 규칙을 그대로 적용해야 한다. (POST-08)
- **FR-065**: 아래 상자에 마지막 임시 저장 시각을 시:분(한국 시간)으로 보여야 한다. (POST-08)
- **FR-066**: 임시 글이 있을 때 글쓰기 화면을 열면 1번만 불러올지 물어야 한다. 불러오면 저장한 값으로 모든 칸을 채우고(그 사이 카테고리가 지워졌으면 `카테고리 없음`), 불러오지 않으면 빈 화면으로 시작하되 임시 글은 다음 저장 때 덮어쓴다. (POST-08)
- **FR-067**: 발행에 성공해 글 상세로 이동하면 임시 글을 지우고(발행 직전 2초 안의 입력도 다시 저장되지 않아야 함), 발행이 실패하면 지우지 않아야 한다. (POST-08)
- **FR-068**: 같은 브라우저를 쓰는 다른 회원의 임시 글은 보이지 않아야 하고, 브라우저의 임시 저장 공간을 쓸 수 없는 환경에서도 글쓰기·발행은 오류 없이 되어야 하며, 글 수정 화면에서는 임시 저장·불러오기를 하지 않아야 한다. (POST-08)

### Key Entities *(include if feature involves data)*

- **글 (Post)**: 한 블로그에 속한 글. 제목(1~100자), 정화된 본문, 본문 글자(요약·글자 수용), 공개 설정(공개/비공개), 선택적 카테고리 1개, 조회수(0 이상, 같은 사람은 하루 1번만 셈), 작성 시각(정렬 기준, 수정해도 그대로), 수정 시각을 가진다. 지우면 댓글·공감·태그 연결이 함께 사라진다.
- **카테고리 (Category)**: 블로그 주인이 만든 분류 (블로그 관리 영역에서 관리). 글은 같은 블로그의 카테고리만 가질 수 있고, 카테고리가 지워지면 글은 `카테고리 없음`이 된다.
- **태그 (Tag)**: 마을 전체에서 이름(소문자, 1~20자)이 하나뿐인 꼬리표. 글과 여러 대 여러 관계이며 글 하나에 최대 10개. 글이 지워져도 태그 자체는 남는다.
- **첨부 (Attachment)**: 회원이 올린 사진 또는 파일. 무작위 키, 올린 회원, 종류(사진/파일), 원래 이름, 형식, 크기, 올린 시각을 가진다. 글과는 본문 속 주소로만 이어지며 글보다 먼저 저장된다. 열 수 있는 사람은 그 첨부가 쓰인 글의 공개 설정을 따르고, 어느 글에도 쓰이지 않았으면 올린 회원뿐이다 (FR-059).
- **조회 기록 (POST-06)**: 글, 한국 날짜, 보는 사람(로그인 회원 또는 BLOG-06과 같은 브라우저 식별값). 같은 글·같은 날·같은 사람은 하나만 남는다. IP는 담지 않는다.
- **임시 글 (Draft, POST-08)**: 브라우저마다 회원별 1개. 제목, 카테고리, 공개 설정, 본문, 태그 칸 글자, 저장 시각을 가진다. 회원이 쓰는 그 브라우저 안에만 저장되며 서비스의 저장 데이터에는 더해지지 않는다.
- **글쓰기 보상 기록**: 글 발행으로 받은 경험치·코인 기록 (게임 영역 소관). 글을 지우거나 비공개로 바꿔도 회수하지 않는다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 온보딩을 마친 회원이 글쓰기 화면에 들어가 100자 글을 발행하기까지 처음 쓰는 사람도 3분 안에 끝낼 수 있다.
- **SC-002**: 글쓰기 화면에 보인 글자 수와 보상 안내가 실제 보상 결과와 100% 일치한다 (목록·인용·코드 블록·구분선·빈 문단·공백·이모지 등 21가지 이상 본문 유형에서).
- **SC-003**: 위험한 HTML 6종(스크립트, `onerror`, `onclick`, `javascript:` 링크, 프레임, 스타일)과 외부·미등록 주소의 사진·파일 카드가 저장된 글에 0건 남는다.
- **SC-004**: 비공개 글과 그 글에 쓰인 사진·파일은 주인이 아닌 사람에게 어떤 목록·집계·주소로도 0건 노출된다.
- **SC-005**: 저장 오류가 나도 입력한 제목·카테고리·공개 설정·본문·태그의 손실이 0건이다.
- **SC-006**: 화면에서 정상 입력으로 낼 수 있는 오류 문구의 100%가 한국어이고 무엇을 고치면 되는지 알려준다.
- **SC-007**: 글 목록 화면이 1초 안에 표시되고, 비정상 페이지 값을 넣어도 서버 오류 화면이 0건이다.
- **SC-008**: 375px 화면에서 글쓰기·글 상세(사진·파일 카드 포함)·목록 화면에 가로 스크롤이 없다.
- **SC-009**: 사진 여러 장·파일을 한 번에 넣었을 때 규칙에 맞는 첨부는 100% 본문에 들어가고, 내려받은 파일 이름이 올린 원래 이름과 100% 같다.
- **SC-010**: (POST-08) 새 글을 쓰다 새로고침·탭 닫기·로그인 만료로 벗어나도, 마지막 입력 후 2초가 지났다면 같은 브라우저에서 다시 열었을 때 내용 손실이 0건이다.
- **SC-011**: 같은 사람(로그인 회원은 기기 수와 상관없이)이 한국 시간 같은 날 같은 글을 여러 번 열어도 조회수는 1만 오른다.

## Assumptions

- 사용자는 방문자(로그인 안 함), 회원(온보딩 완료), 관리자다. 관리자가 남의 글을 지우는 기능은 AUTH-08, 글쓰기 보상 수치(경험치 30·코인 30·하루 3번)와 원장 규칙은 GAME-05, 카테고리 만들기·순서는 BLOG-05, 공감·댓글·이웃은 SOC 영역 소관이며 이 spec은 그 규칙을 따른다.
- 글 목록의 1초 표시(NF-07), 375px 대응(NF-06), HTML 정화(NF-03), 한국어 오류 문구(NF-19)는 비기능 요구사항을 그대로 적용한다.
- 공개 설정·카테고리에 규칙 밖 값을 조작해 보냈을 때는 저장을 거부하는 것이 요구사항이며, 지금은 정해진 한국어 문구 없이 기본 오류 문구가 보인다 (화면 조작으로는 생기지 않음).
- 첨부 파일 저장 위치는 지금 서버 디스크이며, 배포 환경 결정(NF-08)에 따라 바뀔 수 있다. 사용자에게 보이는 동작은 같아야 한다.
- POST-08은 원천 문서의 (제안) 초안(2초 멈춤 후 저장, 회원별 1개, 새 글에만, 발행 성공 시 삭제)을 이 spec의 작업 기준으로 삼는다. 임시 글은 그 브라우저에만 저장하므로(2026-10-07 결정) 다른 기기나 다른 브라우저에서는 복구되지 않고, 브라우저 데이터를 지우면 함께 사라진다. 서비스의 저장 데이터 구조는 바뀌지 않는다.
- 조회수의 하루 1번 기준(FR-048)과 비공개 글 첨부 막기(FR-059)는 2026-10-07 결정으로 정한 목표 동작이다. 지금 구현은 열 때마다 세고, 첨부 주소를 알면 누구나 열 수 있으므로 바꿔야 한다. "하루"(한국 시간 날짜)와 "같은 사람"(온보딩을 마친 로그인 회원은 회원, 로그인하지 않은 방문자와 온보딩 전 회원은 브라우저 식별값)의 정의는 블로그 방문자 수(BLOG-06)와 같다.
- 관리자도 남의 글을 열면 조회수에 포함되고, 남의 비공개 글과 그 글의 사진·파일은 관리자도 볼 수 없다 (현재 동작 유지, 첨부는 FR-059).
- Out of scope: 4.3 글 영역에는 `❌ 제외`로 표시된 요구사항 ID가 없다. 이 spec은 관리자 글 관리(AUTH-08), 보상 계산(GAME-05), 공감·댓글(SOC 영역)을 다시 정의하지 않는다. 여러 기기 사이에서 임시 글을 이어 쓰는 기능(서비스 쪽 임시 글 저장)은 이번 범위가 아니다.

### 원천 문서의 열린 질문

아래는 아직 정해지지 않은 질문이다. 정해질 때까지 **현재 동작을 기본으로** 가정하며, (제안)은 채택하지 않는다.

**POST-01**
- 실수로 페이지를 벗어날 때 경고를 띄울까? → 기본: 경고 없음 (POST-08과 함께 결정).
- 삭제한 글의 보상을 회수할까? → 기본: 회수하지 않음 (GAME-05와 같음).
- (제안) 남의 글 수정 조작 시 오류 화면 대신 `내가 쓴 글만 고칠 수 있어요`? → 기본: 오류 화면 유지.
- 발행 안내가 새로고침·다른 사람이 같은 주소를 열 때도 다시 보인다. 주인에게만 한 번만? → 기본: 지금처럼 주소 표시만 보고 띄움.
- 요청이 처리 한도(약 1MB)를 넘으면 `글이 너무 길어요` 전에 거절된다. 화면에서 20만 자를 미리 막을까? → 기본: 미리 막지 않음.
- (제안) 제목 최대 100자 → 200자? → 기본: 100자.
- (제안) 글자 속 코드 도구 버튼 추가? → 기본: 입력 문법·단축키로만.
- (제안) 글 종류 선택과 종류별 안내 문구? → 기본: 글 종류 없음.
- (제안) 관리자도 글 상세에서 남의 글 수정·삭제? → 기본: 관리 화면에서 삭제만 (AUTH-08).

**POST-02**
- "이웃에게만 공개"가 필요할까? → 기본: 공개/비공개 둘만.
- 비공개 글 탭 제목을 주인에게는 실제 제목으로? → 기본: `글 | BlogCabin`.
- 비공개로 바꾸면 댓글 단 사람이 자기 댓글을 못 본다. 그대로 둘까? → 기본: 그대로.
- 잘못된 공개 설정 값의 한국어 문구(예: "공개 설정을 다시 골라 주세요")? → 기본: 정하지 않음.
- (제안) 관리자의 비공개 글 열람 허용? → 기본: 관리자도 404.
- (제안) 블로그 관리에서 공개 설정 일괄 변경? → 기본: 글마다 수정 화면에서.

**POST-03**
- 새 글 기본 카테고리를 첫 번째 카테고리로? → 기본: `카테고리 없음`.
- `0`, `abc`, `1.5` 등 조작 값에도 한국어 문구 하나로? → 기본: 범위 초과만 `잘못된 요청이에요`.
- 목록 카드의 카테고리 배지도 눌리게? → 기본: 카드 전체가 글 상세 링크.
- (제안) 카테고리 필수화 / 카테고리 없을 때 만들기 안내 / 내 블로그에 없는 카테고리 저장 거부와 문구 / 블로그 홈에 `카테고리 없음 (N)` 항목 / 같은 카테고리 다른 글 5개 → 기본: 모두 채택하지 않음.

**POST-04**
- 10개·20자 초과 시 조용히 빼지 말고 안내할까? → 기본: 조용히 뺌.
- 쓰이지 않게 된 태그를 지울까? → 기본: 남김.
- 대문자 태그 주소도 소문자로 찾을까? → 기본: 빈 목록.
- `c#` 같은 태그를 만들 수 없는데 괜찮을까? → 기본: `#`은 구분자.
- 주인에게는 태그별 글에 자기 비공개 글도 보여줄까? → 기본: 공개 글만.
- (제안) 태그 수 10개 → 20개 / 블로그별 태그 목록과 블로그 안 태그 모아보기 → 기본: 채택하지 않음.
- (결정됨) 태그 칸 300자 초과 문구는 `태그는 모두 합쳐 300자까지예요` → FR-007에 반영.

**POST-05**
- 한 페이지 8개가 적당할까? → 기본: 8개.
- "더 보기"·무한 스크롤로 바꿀까? → 기본: 페이지 번호.
- 마지막보다 큰 페이지 번호에서 마지막 페이지를 보여줄까? → 기본: 빈 목록.
- 비공개였다가 공개한 글을 공개 시각으로 정렬할까? → 기본: 작성 시각.
- 목록 규칙(8개·정렬·페이지 번호)을 확인하는 자동 시험을 더할까? → 기본: 지금은 없음 (plan에서 검토).
- (제안) 넓은 화면 2열 / 요약 3줄 / 요약에서 코드 블록 글자 제외 / 첫 사진 썸네일 → 기본: 채택하지 않음.
- (해결됨) 블로그 홈 카테고리 값의 비정상 값은 전체 글 → FR-043에 반영.

**POST-06**
- (제안) 관리자 조회도 세지 않을까? → 기본: 관리자도 센다.
- 검색 로봇이 연 것도 셀까? → 기본: 구분하지 않고 센다.
- 세는 일을 화면 그리기 밖으로 옮길까? (미리 불러오기 때 세어질 가능성 포함) → 기본: 현재 방식, plan에서 FR-049와 함께 검토.
- 조회수에 천 단위 쉼표? → 기본: 쉼표 없음.
- (제안) 블로그 관리에 전체 조회수·많이 본 글 5개 → 기본: 채택하지 않음.

**POST-07 / POST-09**
- 배포 시 파일 저장 위치? → 기본: 서버 디스크 (NF-08과 함께 결정).
- 글을 지우거나 사진을 빼면 파일도 지울까? → 기본: 남김 (FR-058 알려진 문제).
- 한 글의 사진 수, 회원별 하루 올리기 양 제한? → 기본: 제한 없음.
- 사진만 있고 글자가 없는 글 허용? → 기본: `본문을 적어 주세요`로 막음.
- 대체 글(`alt`) 입력? → 기본: 빈 값.
- 목록 카드에 첫 사진 썸네일? → 기본: 없음.
- 바이러스 검사가 필요할까? → 기본: 형식·크기만 확인.
- MP3·MP4를 글 안에서 바로 재생? → 기본: 내려받기 카드.

**POST-08**
- (제안) 자동 저장 간격 2초 → 0.6초? → 기본: 2초 (초안 값).
- 저장 시각 문구? (제안: `작성 중인 글은 이 브라우저에 자동 저장됩니다.` / `임시 저장됨 14:05`) → 기본: 시:분 표시만 정하고 문구는 미정.
- 불러올지 묻는 방식과 문구? (제안: 확인 창 `작성 중이던 글이 있어요. 불러올까요?`) → 기본: 1번 묻는다는 것만 정하고 방식은 미정.
- 글 수정에도 임시 저장? → 기본: 새 글에만.
- 로그아웃할 때 임시 글을 지울까? → 기본: 지우지 않음.
- 임시 저장이 생기면 POST-01의 "페이지 벗어날 때 경고"는 뺄까? → 기본: 경고 없음 유지.
