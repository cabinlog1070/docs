- Q: 블로그 방문자 수를 셀 때 로그인한 회원도 브라우저 식별값으로 구별할까(같은 회원이 휴대폰·PC에서 보면 2명), 회원 기준으로 하루 1번 셀까? → A: 온보딩을 마친 로그인 회원은 회원 기준으로 한국 시간 하루 1번 센다(기기·브라우저 수와 상관없음). 방문자(로그인하지 않은 사람과 온보딩 전 회원, 이 spec의 "방문자")만 브라우저 식별값으로 하루 1번 센다. "하루"의 정의는 POST-06 조회수(003 글쓰기 spec)와 같다. (FR-039)
- Q: 내 블로그에서 하는 검색은 마을 전체의 공개 글·블로그를 찾는가, 이 블로그 글만 찾는가, 그리고 방문자가 남의 블로그 홈에서도 검색할 수 있는가? → A: 요약 표(BLOG-07)대로 마을 전체의 공개 글과 블로그를 찾는다. 검색창은 온보딩을 마친 회원이 자기 블로그 홈(내 집)을 볼 때만 보이고, 방문자와 남의 블로그 홈에는 검색이 없다. 비공개 글은 자기 글이라도 결과에 나오지 않는다(마을 검색이므로). (FR-042)
- Q: 검색은 어떤 항목에서 찾고, 결과는 어떻게 나눠 보여주며, 검색어 규칙과 결과가 없을 때 문구는 무엇인가? → A: 글은 제목·본문·태그, 블로그는 블로그 이름·닉네임·블로그 주소에서 찾는다. 결과는 `블로그` 구역(최대 5개, 이름 순이 아니라 가장 최근에 공개 글을 쓴 순)과 `글` 구역(글 카드, 한 페이지 8개, 최신순)으로 나눈다. 검색어는 앞뒤 공백을 뺀 1~50자이고, 비어 있으면 `검색어를 입력해 주세요`, 결과가 없으면 `'{검색어}'에 맞는 글이나 블로그가 없어요`를 보여준다. (FR-043)

## User Scenarios & Testing *(mandatory)*

BlogCabin에서 회원 한 명은 블로그 하나를 가진다. 블로그는 `/@주소`로 누구에게나 열리고, 맨 위에 주인이 꾸민 미니룸(배경 + 캐릭터)이, 아래에 카테고리와 글 목록이 보인다. 주인은 블로그 이름·소개와 카테고리를 관리한다. 방문자 수(BLOG-06)와 내 블로그에서 하는 마을 검색(BLOG-07)은 아직 만들지 않은 목표 기능이다.

보는 사람은 세 가지다: **주인**(이 블로그를 가진 회원), **다른 회원**(온보딩을 마친 다른 회원), **방문자**(로그인하지 않은 사람, 또는 로그인했지만 온보딩 전인 사람).

### User Story 1 - 온보딩을 마치면 내 블로그가 하나 생긴다 (Priority: P1)

새로 가입한 회원은 온보딩에서 닉네임·캐릭터와 함께 블로그 이름과 블로그 주소를 적고 [광장으로 출발! 🚀]을 누른다. 그 순간 블로그가 하나 만들어지고, 광장의 `내 집`이 내 블로그로 연결된다. 블로그를 따로 만들거나 지우는 단계는 없다.

**Why this priority**: 블로그가 없으면 글쓰기·꾸미기·교류가 모두 불가능하다. 서비스의 출발점이다.

**Independent Test**: 새 회원으로 온보딩을 마친 뒤 광장의 `내 집`을 통해 `/@{내 주소}`가 열리고, 블로그가 정확히 1개이며 이름·주소·소개·배경·카테고리가 기본값대로인지 확인한다.

**Acceptance Scenarios**:

1. **Given** 로그인했고 온보딩 전인 회원, **When** 블로그 이름 `진행의 개발 일지`, 주소 `jinhaeng`을 적고 온보딩을 마치면, **Then** 블로그가 정확히 1개 생기고 이름·주소는 적은 값, 소개는 빈 값, 미니룸 배경은 초원, 카테고리는 "일상" 1개다.
2. **Given** 온보딩 화면, **When** 이미 있는 주소로 보내면, **Then** `이미 있는 주소예요`가 칸 아래에 보이고, 입력한 값은 그대로 남으며, 블로그·프로필·카테고리·아이템·코인 중 어느 것도 저장되지 않는다.
3. **Given** 온보딩 화면, **When** 블로그 이름에 공백만 적어 보내면, **Then** `블로그 이름을 적어 주세요`가 보이고 블로그가 만들어지지 않는다.
4. **Given** 온보딩을 마친 회원, **When** 온보딩 화면에 다시 들어가거나 열어 둔 온보딩 화면에서 다시 보내면, **Then** 블로그를 새로 만들지 않고 광장으로 이동하며 블로그는 그대로 1개다.
5. **Given** 온보딩 전 회원이 두 탭에 온보딩 화면을 열어 둠, **When** 거의 동시에 두 탭에서 보내면, **Then** 블로그는 1개만 생기고, 늦은 쪽에는 `잠깐 문제가 생겼어요` 오류 화면이 뜬다.
6. **Given** 블로그가 없는 새 서비스, **When** 관리자 계정 준비 작업을 실행하면, **Then** 관리자 블로그 `/@notice`(이름 `BlogCabin 공지사항`, 카테고리 "공지" 1개)가 생기고, 다시 실행해도 블로그가 늘지 않는다.

### User Story 2 - 누구나 `/@주소`로 블로그 홈을 구경한다 (Priority: P1)

방문자든 회원이든 `/@주소`로 들어오면 그 블로그 홈이 열린다. 맨 위에는 주인이 장착한 배경 위에 캐릭터와 닉네임이 보이는 미니룸, 그 아래 블로그 이름·소개·`@주소 · 글 N · 이웃 N`, 왼쪽에는 카테고리 목록, 오른쪽에는 글 목록이 보인다. 카테고리와 페이지를 골라 글을 찾아보고, 글 카드를 눌러 글 상세로 간다. 보는 사람에 따라 주인용 버튼 또는 이웃 버튼이 보인다.

**Why this priority**: 블로그 홈은 글을 보여주고 다른 사람이 내 블로그를 발견하는 핵심 화면이다. 미니룸은 게임 보상(꾸미기)이 눈에 보이는 자리다.

**Independent Test**: 글이 몇 개 있는 블로그를 방문자·다른 회원·주인으로 각각 열어, 미니룸·정보 줄·카테고리·글 목록·버튼이 표시 규칙대로 보이는지, 잘못된 주소가 404 화면으로 가는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 로그인하지 않은 방문자, **When** `/@jinhaeng`을 열면, **Then** 주소창에 `/@jinhaeng`이 그대로 남고, 맨 위에서 주인이 장착한 배경·캐릭터·닉네임을 보며, 블로그 정보 오른쪽에 버튼이 없다.
2. **Given** 블로그 주인, **When** 자기 블로그 홈을 열면, **Then** [✏️ 글쓰기] [🎨 꾸미기] [⚙️ 관리]가 보이고, 비공개 글이 목록과 카테고리 글 수에 포함되며 카드에 `🔒 비공개` 배지가 붙는다.
3. **Given** 온보딩을 마친 다른 회원, **When** [+ 이웃 추가]를 누르면, **Then** 버튼이 [✓ 이웃]으로 바뀌고 `이웃 N`이 1 늘어나며, 다시 누르면 되돌아간다.
4. **Given** 블로그 홈, **When** 왼쪽에서 카테고리를 누르고 이어서 2페이지를 누르면, **Then** 그 카테고리 글만 보이고 왼쪽 항목이 노란 배경이며, 2페이지에서도 카테고리가 유지된다.
5. **Given** 누구나, **When** 없는 주소(`/@nobody_here`), 대문자가 섞인 주소(`/@Notice`), 다른 블로그의 글 ID, `/@notice/abc`·`/@notice/0`·`/@notice/012`·`/@notice/1e1`·`/@notice/2147483648`, 남의 비공개 글을 열면, **Then** 모두 같은 404 화면(🧭 `길을 잃었어요` / `찾는 블로그나 글이 없거나, 비공개 글이에요.` / [광장으로 돌아가기])이 보이고 서버 오류 화면은 나오지 않는다.
6. **Given** 글이 없는 블로그, **When** 방문자와 주인이 각각 열면, **Then** 둘 다 `🌱 아직 글이 없어요.`를 보고, [첫 글 쓰기]는 주인에게만 보인다.
7. **Given** 블로그 홈, **When** 주소의 카테고리 값에 `1.5`, `Infinity`, `99999999999`처럼 이상한 값을 넣으면, **Then** 오류 없이 전체 글이 보인다.
8. **Given** 375px 너비 화면, **When** 주인으로 블로그 홈을 열면, **Then** 가로 스크롤이 없고, 주인 버튼 글자가 두 줄로 쪼개지지 않는다.

### User Story 3 - 주인이 블로그 이름과 소개를 고친다 (Priority: P2)

주인은 블로그 홈의 [⚙️ 관리]로 블로그 관리 화면에 들어가 "기본 정보"에서 이름과 소개를 고치고 [저장]한다. 바뀐 이름은 블로그 홈, 광장의 집, 글 카드 등에 바로 반영된다. 주소는 보여주기만 하고 바꿀 수 없다.

**Why this priority**: 블로그 정체성을 다듬는 기본 관리 기능이지만, 기본값으로도 블로그는 동작한다.

**Independent Test**: 주인으로 이름·소개를 바꿔 저장한 뒤 블로그 홈 제목·소개 줄·광장 집 부제가 바뀌었는지, 잘못된 값에 정해진 문구가 나오는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 블로그 관리 화면의 주인, **When** 이름을 `  새 이름  `으로 적어 저장하면, **Then** 다른 화면으로 이동하지 않고 [저장] 왼쪽에 `저장했어요 ✓`가 보이며, 이름은 `새 이름`으로 저장되어 블로그 홈 제목과 광장 내 집 부제에 보인다.
2. **Given** 블로그 관리 화면, **When** 이름에 공백만 넣고 저장하면, **Then** `블로그 이름을 적어 주세요`가 보이고 저장된 값은 그대로다.
3. **Given** 블로그 관리 화면, **When** 161자 소개를 보내면, **Then** `소개는 160자까지예요`가 보인다.
4. **Given** 소개가 있는 블로그, **When** 소개를 비우고 저장하면, **Then** 블로그 홈에서 소개 줄이 사라진다.
5. **Given** 주인, **When** 저장 요청에 주소 같은 다른 값을 넣어 보내면, **Then** 이름·소개만 바뀌고 주소는 그대로다.
6. **Given** 로그인하지 않은 사람, **When** 블로그 관리 화면을 열면, **Then** 첫 화면으로 이동한다. 온보딩 전 회원은 온보딩 화면으로 이동한다.

### User Story 4 - 주인이 카테고리를 만들고 정리한다 (Priority: P2)

주인은 블로그 관리 화면의 "카테고리"에서 카테고리를 추가하고, 이름을 바꾸고, ▲▼로 순서를 바꾸고, 지운다. 모든 변경은 버튼을 누르는 즉시 저장되고, 블로그 홈 왼쪽 목록과 글쓰기 카테고리 선택에 같은 순서로 반영된다.

**Why this priority**: 글이 늘어날수록 정리가 필요하지만, 기본 카테고리 "일상"만으로도 글쓰기는 가능하다.

**Independent Test**: 주인으로 카테고리 추가·이름 바꾸기·순서 바꾸기·삭제를 차례로 해 보고, 블로그 홈 왼쪽 목록과 글의 카테고리 배지가 그에 맞게 바뀌는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 카테고리 "일상"이 있는 주인, **When** `  여행  `을 적고 [추가](또는 Enter)를 누르면, **Then** `여행`이 목록 맨 아래에 추가되고 입력칸이 비워진다.
2. **Given** "일상"·"여행"이 있는 블로그, **When** "여행"의 이름을 "일상"으로 바꾸면, **Then** `이미 있는 카테고리예요`가 그 줄 아래에 보이고 고친 이름이 칸에 남는다.
3. **Given** 다른 블로그에 "여행"이 있음, **When** 내 블로그에 "여행"을 추가하면, **Then** 추가된다.
4. **Given** 카테고리 3개, **When** 맨 아래 카테고리의 ▲를 누르면, **Then** 바로 위 카테고리와 순서가 바뀌고 블로그 홈 왼쪽 목록과 글쓰기 카테고리 선택도 같은 순서가 된다. 맨 위의 ▲와 맨 아래의 ▼는 눌리지 않는다.
5. **Given** 글 2개가 든 카테고리, **When** [삭제] → 확인 창 `'{이름}' 카테고리를 지울까요? 글은 남고 '카테고리 없음'이 돼요.`에서 확인하면, **Then** 카테고리는 사라지고 글 2개는 남아 카테고리 배지 없이 `전체 글`에서만 보인다. 확인 창에서 취소하면 아무것도 바뀌지 않는다.
6. **Given** 다른 블로그의 카테고리, **When** 그 카테고리를 대상으로 이름 바꾸기·삭제·순서 바꾸기를 요청하면, **Then** 그 카테고리는 바뀌지 않는다.
7. **Given** 주인, **When** 카테고리 번호를 범위 밖 값(`99999999999`)으로 조작해 이름 바꾸기를 요청하면, **Then** 서버 오류 없이 `잘못된 요청이에요`가 돌아오고 아무것도 바뀌지 않는다.

### User Story 5 - 블로그 방문자 수를 본다 (Priority: P3, 미구현 목표)

누구나 블로그 홈 상단 정보 줄 끝에서 `오늘 방문 N · 전체 방문 N`을 본다. 주인이 아닌 사람이 블로그 홈을 열면 한국 시간 하루에 한 번 방문으로 센다. 로그인 회원은 회원 기준으로, 방문자는 브라우저 기준으로 같은 사람인지 가린다.

**Why this priority**: 우선순위 C(있으면 좋음). 주인에게 동기를 주지만 글쓰기 흐름에는 필수가 아니다.

**Independent Test**: 로그인하지 않은 서로 다른 브라우저 두 개, 두 기기에서 로그인한 같은 회원, 주인 계정으로 같은 블로그 홈을 여러 번 열어, 숫자가 사람(회원은 회원, 방문자는 브라우저)·날짜 기준으로만 오르는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 처음 오는 방문자, **When** 블로그 홈을 열면, **Then** `오늘 방문`과 `전체 방문`이 각각 1 오르고 새로고침 없이 화면에 보인다.
2. **Given** 오늘 이미 방문한 같은 브라우저, **When** 새로고침하거나 카테고리·페이지를 옮기면, **Then** 숫자가 더 오르지 않는다.
3. **Given** 로그인하지 않은 다른 브라우저(다른 방문자), **When** 같은 블로그 홈을 열면, **Then** 1 오른다.
4. **Given** 블로그 주인, **When** 자기 블로그 홈을 열거나 방문 기록을 직접 요청하면, **Then** 오르지 않는다.
5. **Given** 스크립트를 실행하지 않는 요청(예: 로봇), **When** 블로그 홈을 가져가면, **Then** 오르지 않는다.
6. **Given** 한국 시간 0시가 지남, **When** 블로그 홈을 열면, **Then** `오늘 방문`은 0부터 다시 세고 `전체 방문`은 줄지 않는다.
7. **Given** 오늘 PC에서 로그인한 채 이 블로그 홈을 연 회원(온보딩 완료), **When** 같은 날 휴대폰(다른 브라우저)에서 로그인한 채 다시 열면, **Then** 숫자가 오르지 않는다.
8. **Given** 같은 브라우저에서 오늘 이미 센 회원 A, **When** 회원 B가 같은 브라우저로 로그인해 같은 블로그 홈을 열면, **Then** B는 다른 사람이므로 1 오른다.

### User Story 6 - 내 블로그에서 마을의 글과 블로그를 검색한다 (Priority: P3, 미구현 목표)

검색은 광장이 아니라 **내 집(내 블로그)에 들어가서** 한다. 회원은 자기 블로그 홈의 검색창에 검색어를 넣어 마을 전체의 공개 글과 블로그를 찾고, 결과를 `블로그` 구역과 `글` 구역으로 나눠 본다.

**Why this priority**: 우선순위 S이지만 아직 만들지 않았다. 광장에 검색을 두지 않는 대신 내 집에서 마을의 글과 블로그를 찾게 해 준다.

**Independent Test**: 여러 블로그에 공개 글·비공개 글이 섞인 상태에서, 주인으로 내 블로그 홈의 검색창에 제목·본문·태그·블로그 이름·닉네임·주소에 든 단어를 각각 넣어 두 구역의 결과가 정해진 대상·순서·공개 규칙을 따르는지, 방문자와 남의 블로그 홈에는 검색창이 없는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 내 블로그 홈의 회원(주인), **When** 다른 블로그의 공개 글 제목에 든 검색어로 검색하면, **Then** 그 글이 `글` 구역에 글 카드(윗줄 `{닉네임} · {블로그 이름}`)로 보인다.
2. **Given** 광장 화면, **When** 검색 기능을 찾으면, **Then** 광장에는 검색이 없다.
3. **Given** 다른 사람의 비공개 글과 내 비공개 글에 검색어가 있음, **When** 검색하면, **Then** 두 글 모두 결과에 나오지 않는다.
4. **Given** 방문자(온보딩 전 회원 포함) 또는 남의 블로그 홈을 보는 회원, **When** 블로그 홈을 열면, **Then** 검색창이 없다.
5. **Given** 블로그 이름·닉네임·블로그 주소 중 하나에 검색어가 든 블로그 7개, **When** 검색하면, **Then** `블로그` 구역에 가장 최근에 공개 글을 쓴 순으로 5개만 보이고, 누르면 그 블로그 홈(`/@주소`)으로 간다.
6. **Given** 태그에만 검색어가 든 공개 글 9개, **When** 검색하면, **Then** `글` 구역 1페이지에 최신순 8개와 페이지 번호가 보이고, 2페이지에 나머지 1개가 보인다.
7. **Given** 검색창, **When** 공백만 넣고 검색하면, **Then** `검색어를 입력해 주세요`가 보이고 검색하지 않는다.
8. **Given** 어디에도 들어 있지 않은 검색어 `zzqq`, **When** 검색하면, **Then** `'zzqq'에 맞는 글이나 블로그가 없어요`가 보인다.

### Edge Cases

- 블로그 이름 41자 이상, 소개 161자 이상, 카테고리 이름 21자 이상: 입력칸에서 더 써지지 않고, 그 제한을 거치지 않은 요청은 서버가 `블로그 이름은 40자까지예요` / `소개는 160자까지예요` / `카테고리 이름은 20자까지예요`로 막는다.
- 블로그 관리에서 이름·소개 오류가 둘 이상이면 첫 번째 하나(이름 → 소개 순)만 보이고, 두 칸은 마지막으로 저장된 값으로 되돌아간다.
- 카테고리 추가에서 오류가 나면 문구는 보이지만 입력칸은 비워진다 (현재 동작).
- 카테고리를 모두 지울 수 있다. 그러면 관리 화면에는 추가 칸만 보이고, 글쓰기에서는 `카테고리 없음`만 고를 수 있다.
- `Dev`와 `dev`처럼 대소문자만 다른 카테고리 이름은 다른 이름으로 본다.
- 주소의 카테고리 값이 없는 번호이거나 다른 블로그의 카테고리면 목록이 비고 제목은 `전체 글 0개`, 왼쪽 목록에 선택된 항목이 없다.
- 주소의 페이지 값이 마지막 페이지보다 크면 목록이 비고 `🌱 아직 글이 없어요.`가 뜨지만, 제목의 `N개`는 그대로다. 글이 8개 이하면 페이지 번호도 숨겨진다 (현재 동작).
- 주인이 볼 때 `전체 글 (N)`은 공개 글만 세고, 목록 제목 `N개`와 카테고리 글 수는 비공개를 포함해 숫자가 다를 수 있다 (현재 동작).
- 장착한 캐릭터·배경의 그림이 없으면 오류 문구 없이 회색 기본 몸통과 초원 장면으로 그린다.
- 로그인했지만 온보딩 전인 사람은 블로그 홈을 방문자와 똑같이 보고(버튼·검색창 없음), 방문자 수에도 방문자로(브라우저 식별값 기준) 센다.
- 관리자 블로그 주소 `notice`는 예약어가 아니라서, 관리자 계정 준비보다 먼저 회원이 `notice`를 쓰면 관리자 블로그를 만들지 못한다.
- 로그인하지 않은 상태에서 식별값이 없는 브라우저가 두 탭을 거의 동시에 처음 열면 방문자 수가 2번 오를 수 있다 (막지 않는다).
- 같은 브라우저라도 로그인한 상태(회원 기준)와 로그인하지 않은 상태(브라우저 식별값 기준)는 따로 센다. 오늘 로그인해서 센 회원이 로그아웃하고 다시 열면 1번 더 오를 수 있고(막지 않는다), 로그아웃한 주인도 방문자로 센다.
- 방문으로 센 회원이 나중에 탈퇴해도 이미 센 `전체 방문`은 줄지 않는다.
- 방문 기록이 실패해도 블로그는 그대로 보이고 숫자는 처음 값으로 남는다.
- 검색어는 앞뒤 공백을 빼고 찾는다. 검색칸은 50자까지만 써지고, 그 제한을 거치지 않은 50자 초과 요청은 서버 오류 없이 검색하지 않는다.
- 검색어에 맞는 블로그만 있거나 글만 있으면, 결과가 없는 구역은 그리지 않는다. 둘 다 없을 때만 `'{검색어}'에 맞는 글이나 블로그가 없어요`가 보인다.
- 이름·닉네임·주소는 맞지만 공개 글이 하나도 없는 블로그는 `블로그` 구역에서 공개 글이 있는 블로그들 뒤에 놓인다. 비공개 글만 있는 블로그도 같다(비공개 글을 쓴 시각은 순서에 쓰지 않는다).

**블로그 생성 (BLOG-01)**

- **FR-001**: 시스템은 온보딩을 마친 회원 한 명당 블로그를 정확히 1개 두어야 한다(MUST). 같은 회원의 두 번째 블로그는 동시 요청이나 직접 데이터 입력을 포함한 어떤 경로로도 만들어지지 않아야 한다. (BLOG-01)
- **FR-002**: 시스템은 온보딩을 마치는 순간 블로그를 자동으로 만들어야 한다(MUST). 이름·주소는 온보딩에서 적은 값, 소개는 빈 값, 미니룸 배경은 초원, 기본 카테고리 "일상" 1개를 함께 만든다. 블로그를 따로 만드는 화면은 없다. (BLOG-01)
- **FR-003**: 시스템은 온보딩에서 블로그 이름(필수, 앞뒤 공백 제거 후 1~40자, 문자 종류 제한 없음)과 블로그 주소(FR-012 규칙)만 받아야 한다(MUST). 이름이 비었으면 `블로그 이름을 적어 주세요`, 40자를 넘으면 `블로그 이름은 40자까지예요`를 보여주고, 오류가 있으면 블로그를 만들지 않으며 입력한 값은 그대로 남기고 해당 칸 아래 안내 자리에 문구를 대신 보여준다. (BLOG-01)
- **FR-004**: 온보딩 처리 중 하나라도 실패하면 블로그, 프로필, 카테고리, 아이템, 코인 중 어느 것도 저장되지 않아야 한다(MUST). (BLOG-01)
- **FR-005**: 이미 온보딩을 마친 회원이 온보딩 화면에 들어오거나 열어 둔 온보딩 화면에서 다시 보내면, 시스템은 블로그를 새로 만들지 않고 광장으로 보내야 한다(MUST). 두 탭에서 거의 동시에 보내면 블로그는 1개만 생기고, 늦은 쪽에는 상황 설명 없이 🚧 `잠깐 문제가 생겼어요` / [다시 시도] [광장으로 돌아가기] 오류 화면이 뜬다 (현재 동작, 원천 문서의 열린 질문 참고). (BLOG-01)
- **FR-006**: 온보딩 화면은 첫 소개 문구 `캐릭터를 골라 광장에 도착하면, 그곳에 내 블로그 집이 생겨요.`를 보여주고, `블로그 이름` 칸(처음 빈 칸, 예시 `예: 진행의 개발 일지`, 최대 40자)과 `블로그 주소` 칸(앞에 `blogville/@`, 예시 `jinhaeng`, 아래 안내 `영문 소문자, 숫자, _ (3~20자)`, 최대 20자, 기본값 없음)을 보여줘야 한다(MUST). 처리 중에는 버튼이 `등록하는 중...`으로 바뀌고 눌리지 않는다. (BLOG-01, BLOG-02)
- **FR-007**: 블로그가 생긴 뒤 광장 아래쪽 집은 이름표 `내 집`과 그 아래 줄의 블로그 이름으로 보이고, 문 앞에서 들어가면 내 블로그 홈으로 가야 한다(MUST). 블로그 관리 화면 오른쪽 위 `내 블로그로 →`도 내 블로그 홈으로 간다. 헤더에는 블로그로 가는 이동 메뉴가 없다. (BLOG-01)
- **FR-008**: 블로그를 추가하거나 지우는 화면·기능은 없어야 한다(MUST). 회원이 삭제되면 그 블로그와 블로그의 카테고리·글도 함께 삭제된다. (BLOG-01)
- **FR-009**: 관리자 계정 준비 작업은 관리자에게 프로필이 없을 때만 관리자 블로그 `/@notice`(이름 `BlogCabin 공지사항`, 소개 `마을 소식과 업데이트를 알려드려요`, 카테고리 "공지" 1개)를 만들어야 하며(MUST), 다시 실행해도 블로그가 늘지 않아야 한다. (BLOG-01)

**블로그 주소 (BLOG-02)**

- **FR-010**: 누구나(로그인하지 않아도) `/@주소`로 그 블로그 홈을 열 수 있어야 하며(MUST), 주소창에는 `/@주소`가 그대로 남아야 한다. (BLOG-02)

- **FR-012**: 블로그 주소는 앞뒤 공백 제거 후 영문 소문자·숫자·`_` 3~20자여야 하고(MUST), 대문자로 입력하면 소문자로 바꿔 저장하며(`JinHaeng` → `jinhaeng`), 서비스 전체에서 하나뿐이어야 한다. 예약어 `admin`, `api`, `town`, `feed`, `shop`, `closet`, `write`, `settings`, `blog`, `onboarding`은 쓸 수 없다. 오류 문구: 형식이 틀림 `주소는 영문 소문자, 숫자, _ 로 3~20자예요` · 예약어 `이 주소는 쓸 수 없어요` · 이미 있음 `이미 있는 주소예요`. (BLOG-02, BLOG-01)
- **FR-013**: 블로그 주소는 한 번 정하면 바꿀 수 없어야 한다(MUST). 블로그 관리 화면에는 `블로그 주소: /@{주소} (주소는 바꿀 수 없어요)`로 보여주기만 하고, 블로그 정보 저장 요청에 주소가 들어 있어도 무시한다. (BLOG-02, BLOG-03)

**내 블로그에서 마을 검색 (BLOG-07, 미구현 목표)**

- **FR-042**: 회원은 광장이 아니라 내 집(내 블로그 홈)에 들어가서 검색할 수 있어야 한다(MUST). 광장에는 검색이 없다. 검색창은 온보딩을 마친 회원이 **자기 블로그 홈**을 볼 때만 보이고, 방문자(온보딩 전 회원 포함)가 보는 블로그 홈과 회원이 보는 남의 블로그 홈에는 없다. 검색 범위는 이 블로그가 아니라 **마을 전체의 공개 글과 블로그**이며, 비공개 글은 자기 글이라도 결과에 나오지 않는다. 검색은 서버에서도 온보딩을 마친 회원만 쓸 수 있게 확인한다: 로그인하지 않았으면 첫 화면으로, 온보딩 전이면 온보딩 화면으로 보낸다(문구 없음). (BLOG-07)
- **FR-043**: 검색어는 앞뒤 공백을 뺀 1~50자여야 한다(MUST). 비어 있으면 `검색어를 입력해 주세요`를 보여주고 검색하지 않으며, 검색칸은 50자까지만 써지고 그 제한을 거치지 않은 50자 초과 요청도 서버 오류 없이 검색하지 않는다. 검색어가 들어 있는 항목을 찾되, 글은 **제목·본문·태그**, 블로그는 **블로그 이름·닉네임·블로그 주소**에서 찾는다. 결과는 두 구역으로 나눠 보여준다: 위의 `블로그` 구역은 맞는 블로그를 최대 5개, 가장 최근에 공개 글을 쓴 순(공개 글이 없는 블로그는 맨 뒤)으로 블로그 이름·닉네임·`@{주소}`와 함께 보여주고, 누르면 `/@주소`로 간다. 아래의 `글` 구역은 맞는 공개 글을 최신순으로 마을 소식과 같은 글 카드(윗줄 `{닉네임} · {블로그 이름}`) 한 페이지 8개와 페이지 번호로 보여주고, 카드를 누르면 `/@주소/글ID`로 간다. 결과가 없는 구역은 그리지 않고, 두 구역 모두 결과가 없으면 `'{검색어}'에 맞는 글이나 블로그가 없어요`를 보여준다. (BLOG-07)

**블로그 홈 화면 (BLOG-01~05 공통)**

- **FR-044**: 블로그 홈은 로그인 없이 누구나 열 수 있어야 하며(MUST), 보는 사람을 주인 / 다른 회원(온보딩 완료) / 방문자(로그인하지 않았거나 온보딩 전)로 나눠 보여줘야 한다. (BLOG-01, BLOG-02, 블로그 홈 공통)
- **FR-045**: 블로그 홈 위쪽에는 미니룸(FR-022), 블로그 이름(누르면 블로그 홈 첫 화면), 소개(비어 있으면 줄 없음), `@{주소} · 글 {N} · 이웃 {N}`이 보여야 한다(MUST). 글 N은 주인이 봐도 **공개 글 수**이고, 이웃 N은 이 블로그 주인을 이웃 추가한 사람 수다. (BLOG-02, BLOG-04, 블로그 홈 공통)
- **FR-046**: 블로그 정보 오른쪽(정보 줄과 아래를 맞추고, 자리가 모자라면 아래 줄로)에는 주인에게 [✏️ 글쓰기](초록, 글쓰기 화면) [🎨 꾸미기](흰색, 꾸미기 화면) [⚙️ 관리](흰색, 블로그 관리 화면), 다른 회원에게 [+ 이웃 추가](하늘색) 또는 [✓ 이웃](흰색), 방문자와 온보딩 전 회원에게는 버튼 없음을 보여줘야 한다(MUST). 이웃 버튼을 누르면 화면이 다시 그려져 버튼과 `이웃 N`이 바뀌며, 누르는 동안 처리 중 표시는 없다 (현재 동작). (BLOG-04, 블로그 홈 공통)
- **FR-047**: 카테고리 상자(768px 이상은 왼쪽 220px 너비로 스크롤해도 화면 위 80px 지점에 붙어 따라오고, 768px 미만은 글 목록 위)는 제목 `카테고리`, `전체 글 (N)`(누가 보든 공개 글 수), `└ {카테고리} (N)`(주인이 보면 비공개 포함, 글이 없으면 `(0)`)을 FR-033 순서로 보여주고, 선택된 항목은 노란 배경 + 굵게 표시해야 한다(MUST). 카테고리 없는 글은 따로 항목이 없고 `전체 글`에서만 보인다. 카테고리를 누르면 그 카테고리 글만 1페이지부터, `전체 글`을 누르면 처음 화면을 보여준다. (BLOG-05, 블로그 홈 공통)
- **FR-048**: 글 목록은 `{카테고리 이름 또는 "전체 글"} N개`(지금 조건의 글 수, 주인이 보면 비공개 포함) 아래 한 페이지 8개, 한 줄에 카드 1개와 페이지 번호로 보여줘야 한다(MUST). 페이지를 옮겨도 고른 카테고리는 유지된다. 카드에는 작성자 줄이 없고, 비공개 글은 주인에게만 `🔒 비공개` 배지와 함께 보이며, 카드를 누르면 `/@주소/글ID`로 간다. (블로그 홈 공통)
- **FR-049**: 보여줄 글이 없으면 `🌱 아직 글이 없어요.`를 보여주고, 주인에게만 [첫 글 쓰기](글쓰기 화면으로) 버튼을 보여줘야 한다(MUST). (블로그 홈 공통)
- **FR-050**: 주소의 카테고리 값이 숫자만 적힌 1~2147483647 정수가 아니면(`abc`, `0`, `-1`, `1.5`, `Infinity`, `99999999999`, `012`, `1e1`) 전체 글을, 없는 번호·다른 블로그의 카테고리면 빈 목록(`전체 글 0개`, 선택 항목 없음, 빈 문구)을, 페이지 값이 1~2147483647 정수가 아니면 1페이지를, 마지막 페이지보다 크면 빈 목록 문구(제목 `N개`는 그대로)를 보여줘야 하며(MUST, 현재 동작), 어떤 값에도 서버 오류 화면이 나오지 않아야 한다. (블로그 홈 공통)
- **FR-051**: 블로그 홈은 최대 너비 1152px, 좌우 여백 16px이고, 375px 너비에서 가로 스크롤이 없어야 한다(MUST). (블로그 홈 공통, BLOG-04)
- **FR-052**: (알려진 문제) 375px 너비에서 주인 버튼([✏️ 글쓰기] [🎨 꾸미기] [⚙️ 관리])의 글자가 두 줄로 쪼개지지 않아야 한다(MUST). 지금은 "글쓰 / 기"처럼 쪼개진다 — 보완 필요. (블로그 홈 공통)

### Key Entities *(include if feature involves data)*

- **블로그**: 회원 한 명에게 딱 하나 딸린 공간. 주인, 주소(서비스 전체에서 하나뿐, 바꿀 수 없음), 이름(1~40자), 소개(0~160자), 장착한 미니룸 배경을 가진다. 주인이 삭제되면 함께 삭제된다. 이름·주소와 주인의 닉네임은 마을 검색(BLOG-07)에서 블로그를 찾는 대상이다.
- **카테고리**: 블로그 안에서 글을 묶는 이름표. 블로그, 이름(블로그 안에서 하나뿐, 1~20자), 순서를 가진다. 지워지면 그 글은 "카테고리 없음"이 된다. 블로그가 삭제되면 함께 삭제된다.
- **회원 프로필**: 블로그 주인의 닉네임과 장착한 캐릭터. 미니룸과 글 카드 작성자 표시에 쓰인다 (AUTH-02).
- **아이템**: 캐릭터 또는 배경. 그림 이름표를 가지며, 회원이 보유한 아이템만 장착할 수 있다 (SHOP-04).
- **글**: 블로그와 (선택) 카테고리에 속하고 제목·본문·태그와 공개/비공개 상태를 가진다. 글 ID는 서비스 전체에서 하나뿐이다 (POST 영역). 공개 글의 제목·본문·태그는 마을 검색(BLOG-07) 대상이다.
- **이웃 관계**: 회원이 다른 블로그 주인을 이웃으로 추가한 관계. 블로그 홈의 `이웃 N`과 이웃 버튼에 쓰인다 (SOC-04).
- **블로그 방문 기록** (BLOG-06, 미구현): 블로그, 한국 날짜, 방문한 사람(온보딩을 마친 로그인 회원이면 회원, 방문자면 브라우저 식별값). 같은 블로그·같은 날·같은 사람은 하나만 남는다. IP는 담지 않는다. 방문한 회원이 탈퇴해도 이미 센 방문 수는 줄지 않는다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 온보딩을 마친 회원의 100%가 블로그를 정확히 1개 가지며, 같은 회원이 온보딩을 두 탭에서 동시에 보내는 시험 10회에서도 블로그가 2개 생기는 경우가 0건이다.
- **SC-002**: 블로그 홈(글 목록 포함)이 열기 요청 후 1초 안에 보인다 (NF-07).
- **SC-003**: 375px 너비에서 블로그 홈과 블로그 관리 화면에 가로 스크롤이 0px이고, 주인 버튼 글자가 두 줄로 쪼개지는 경우가 0건이다 (NF-06).
- **SC-004**: FR-014·FR-050에 나열한 잘못된 주소·글 ID·카테고리·페이지 값을 모두 넣어 보는 시험에서 서버 오류 화면이 0건이고, 각각 정해진 404 화면·전체 글·1페이지가 100% 보인다.
- **SC-005**: 다른 사람의 블로그 이름·소개·카테고리를 바꾸려는 조작 요청이 성공하는 경우가 0건이다.
- **SC-006**: 블로그 이름을 바꾼 뒤 FR-020에 나열한 모든 표시 자리에서 다음 화면을 열 때 100% 새 이름이 보인다.
- **SC-007**: 주인이 블로그 관리 화면에 들어가 카테고리를 하나 추가하고 순서를 바꾸는 일을 1분 안에 마칠 수 있으며, 그 결과가 블로그 홈 왼쪽 목록에 같은 순서로 보인다.
- **SC-008**: (BLOG-06) 같은 사람이 같은 날 같은 블로그 홈을 10번 열어도(로그인 회원은 두 기기에 나눠 열어도) `오늘 방문`은 1만 오르고, 주인이 자기 블로그를 열 때는 0만큼 오른다.
- **SC-009**: (BLOG-07) 회원이 내 블로그에서 검색어를 넣은 뒤 1초 안에 결과가 보이고, 검색 결과에 비공개 글(자기 글 포함)이 나오는 경우가 0건이며, 방문자나 남의 블로그 홈을 보는 회원에게 검색창이 보이는 경우가 0건이다.

## Assumptions

- 온보딩 흐름(닉네임·캐릭터 선택, 가입 보상)은 AUTH-02·AUTH-03, 광장의 `내 집`·이웃집·환영 문구는 TOWN-01, 꾸미기(장착)는 SHOP-04, 비공개 글 규칙은 POST-02, 글 목록 카드·페이지는 POST-05, 태그는 POST 영역, 글 조회수는 POST-06, 이웃 추가는 SOC-04, 검색 결과의 글 카드 모양은 마을 소식(SOC-05)의 spec을 따른다. 이 spec은 그 기능들이 이미 있다고 가정한다.
- 보안·품질 기준은 constitution과 NF-02(권한은 서버에서), NF-06(375px), NF-07(1초), NF-11(로그인 정보 보호), NF-12(다른 사이트 요청 거부), NF-15(규칙을 저장 단계에서도 보장), NF-26(개인정보 최소화)를 따른다.
- 방문자 수(BLOG-06)는 원천 문서의 "목표 명세(제안)"를 이 기능의 목표로 받아들이고, 2026-10-07 Clarifications로 사람 구별 기준을 정했다: "방문" = 같은 사람 한국 시간 하루 1번(POST-06 조회수와 같은 "하루"), 같은 사람 구별 = 온보딩을 마친 로그인 회원은 회원 기준, 방문자(로그인하지 않은 사람·온보딩 전 회원)는 브라우저 식별값(IP 미저장). 방문 기록은 로그인 없이 부르는 처리라서 "모든 상태 변경 처리는 회원 확인으로 시작한다"는 규칙의 예외로 문서화한다고 가정한다.
- "오늘"은 한국 시간 0시 기준이다.
- 검색(BLOG-07)은 요약 표의 "내 블로그에서 마을의 글·블로그를 검색한다"를 따르며, 범위·대상·문구는 2026-10-07 Clarifications로 정했다. 원천 문서 블로그 홈·SOC-05 열린 질문의 (제안)("이 블로그 글만", "제목·본문만")은 채택하지 않는다.
- **Out of scope**:
  - 4.2 블로그(BLOG)에는 `❌ 제외` 상태의 요구사항 ID가 없다.
  - 회원당 블로그 여러 개, 블로그 삭제·초기화, 블로그 주소 변경(옛 주소 연결 포함), 미니룸 가구 배치(SHOP-05)는 이번 범위에 넣지 않는다.

- BLOG-01 (제안): 온보딩 `블로그 이름` 칸을 `{닉네임}의 블로그`로 미리 채울까? → 기본: 빈 칸.
- BLOG-02: 내부 경로로도 블로그 홈이 열리는데 `/@주소`로 이동시킬까? → 기본: 지금처럼 같은 화면을 보여준다.
- BLOG-02 (제안): 대문자 주소(`/@NOTICE`)를 소문자로 바꿔 찾고 이동시킬까? (블로그 홈 열린 질문에도 같은 제안) → 기본: 404.
- BLOG-02 (제안): 없는 블로그만 `없는 블로그예요.`로 따로 보여줄까? → 기본: 없는 글·비공개 글과 같은 404 문구.
- BLOG-02 (제안): 아이디로 가입한 회원의 주소 칸 기본값을 아이디로 채울까? → 기본: 빈 칸.
- BLOG-03: 소개의 줄바꿈을 블로그 홈에서 살려 보여줄까? → 기본: 한 줄로 이어 보임.
- BLOG-03: 오류가 나면 입력값을 남길까? → 기본: 마지막 저장 값으로 되돌아감.
- BLOG-03: 소개 0~160자 규칙을 저장 단계에서도 강제할까? → 기본: 입력 검증만.
- BLOG-03 (제안): 소개 최대 길이 160자 → 200자? → 기본: 160자.
- BLOG-03 (제안): 이 화면에서 닉네임도 바꿀 수 있게 할까? → 기본: 바꿀 수 없음.
- BLOG-03 (제안): 프로필 사진을 올려 블로그 상단에 보여줄까? → 기본: 없음 (캐릭터가 프로필 역할).
- BLOG-04: 미니룸 가구(SHOP-05)와 어떻게 합칠까? → 기본: 이번 범위 밖.
- BLOG-04: 캐릭터 칸에 배경 아이템이 들어가는 것을 저장 단계에서도 막을까? → 기본: 장착 기능만 확인.
- BLOG-04 (제안): 동작 줄이기 설정이면 튀기를 멈출까? → 기본: 늘 튄다.
- BLOG-04 (제안): 튀는 폭을 3px·3초로 줄일까? → 기본: 캐릭터 높이 25%·2초.
- BLOG-04 (제안): 미니룸에 화면 읽기용 설명(예: `미니룸: 바닷가의 고양이`)을 붙일까? → 기본: 없음.
- BLOG-05: 카테고리를 하나도 없게 지워도 될까? → 기본: 허용.
- BLOG-05: 하위 카테고리(2단계)? → 기본: 없음.
- BLOG-05: 추가 오류 시 입력값을 남길까? → 기본: 비워짐.

- BLOG-05: 대소문자만 다른 이름을 같은 이름으로 막을까? → 기본: 다른 이름으로 봄.
- BLOG-05 (제안): 카테고리 30개 제한? → 기본: 제한 없음.
- BLOG-05 (제안): 삭제 확인 창에 글 수를 보여주고 글 0개면 확인 없이 지울까? → 기본: 지금 문구.
- BLOG-05·블로그 홈 (제안): 카테고리 목록에 `카테고리 없음 (N)` 항목을 둘까? → 기본: 없음 (`전체 글`에서만).
- BLOG-06 (제안): 어제 방문 수도 보여줄까? → 기본: 오늘·전체 2개.
- BLOG-06 (제안): 블로그 관리에 최근 7일 방문 막대그래프? → 기본: 없음.
- BLOG-06 (제안): 글 상세를 연 사람도 블로그 방문자로 셀까? → 기본: 블로그 홈만 센다.
- 블로그 홈: 주인에게 `전체 글 (N)`을 비공개 포함 수로 보여줄까? (제안 포함) → 기본: 누구에게나 공개 글 수.
- 블로그 홈: 없는 번호·다른 블로그의 카테고리 값이면 404로 보낼까, 전체 글로 보여줄까? → 기본: 빈 목록(`전체 글 0개`).
- 블로그 홈: 마지막 페이지보다 큰 페이지 값이면 마지막 페이지로 보낼까, 문구를 바꿀까? (POST-05와 함께) → 기본: `🌱 아직 글이 없어요.`
- 블로그 홈: 카테고리를 고른 상태에서 글쓰기로 가면 그 카테고리를 미리 골라 줄까? → 기본: `카테고리 없음`.
- 블로그 홈: 블로그 정보를 한 번 열 때 중복 조회하지 않게 할까? (NF-07) → 기본: 계획 단계에서 판단, 화면 동작은 같음.

- 블로그 홈 (제안): 이웃 버튼 처리 중 막기와 `이웃으로 추가했어요` 안내? → 기본: 없음.
